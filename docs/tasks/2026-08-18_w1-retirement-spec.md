### A2. Форма стаба (точные шаблоны)

**DECISIONS_FULL:**

```
## D-0011
**РЕТИРОВАНО 2026-08-18.** Суперсид: D-0103 (файл SYSTEM_PROMPT.md удалён как дубль).
Полный текст VERBATIM — docs/DECISIONS_ARCHIVE.md, секция `## D-0011`.
```

**FINDINGS** (заголовок сохраняется ДОСЛОВНО, включая тире и
название):

```
## F-48 — <заголовок дословно>
**РЕТИРОВАНО 2026-08-18.** Кодифицирована: <D-номер/правило>; детектор — <имя>.
**Суть.** <одна строка>
Полный текст VERBATIM — docs/FINDINGS_ARCHIVE.md, секция `## F-48`.
```

Жёсткие требования формы (каждое проверяется машинно, A4):

1. заголовок канонического файла НЕ МЕНЯЕТСЯ побайтово (якоря, парсер
   `## F-NN`, extract_decision_section для `## D-NNNN`);
2. тело стаба НАЧИНАЕТСЯ маркером `**РЕТИРОВАНО <YYYY-MM-DD>.**` —
   единственный машинный признак стаба;
3. ЛИМИТ: тело стаба ≤ 4 непустых строк И ≤ 400 байт UTF-8;
4. ровно ОДНА строка-указатель с путём архивного дома своей пары и
   токеном `секция \`## <ID>\``;
5. тело стаба НЕ содержит `**Класс.**`/`**Класс**` и не содержит
   `**Вопрос применимости.**` (обоснование — A5);
6. «суть» — необязательная одна строка под маркером `**Суть.**` (для
   FINDINGS рекомендуется, для DECISIONS не нужна).

### A3. Архивные дома

docs/DECISIONS_ARCHIVE.md и docs/FINDINGS_ARCHIVE.md (решение Б2(A)).
Правила дома: (i) один файл на канонический файл; (ii) секции в
порядке ВОЗРАСТАНИЯ ID; (iii) РОВНО ОДИН `## <ID>` на файл; (iv)
шапка архива — 3–5 строк: чей архив, что здесь VERBATIM, что канон
держит стаб, что реанимация возвращает текст назад; (v) архив НЕ на
бут-пути, диете не подлежит.

Запрещено измерением: секция-приложение внутри канонического файла
(два `## D-NNNN` → extract_decision_section статус duplicate →
escape_check падает). docs/ не входит в парные множества
parity_check — новый файл в docs/ без кит-долга; новый файл в tools/
— кит-долг (handoff).

### A8. Краевые поведения (R11)

1. **Темпоральный: дома ещё нет.** До первого прохода: стабов ноль,
   архивов нет, --check PASS вакуумно (I8). Дом создаёт ТОТ ЖЕ
   builder-коммит, что переносит первый ID; пустой дом «на будущее»
   запрещён. После: дом непуст, пока есть хоть один стаб; удаление
   дома при живых стабах = FAIL. Мир «дом есть, стабов ноль» легален.
2. **Живой пункт очереди.** Запись как НЕИСПОЛНЕННАЯ ремедиация — не
   ретировать; цитирование как прецедент — можно (стаб держит якорь).
   Docstring'и кода, цитирующие F-ID, не правятся этим диспатчем;
   машинного гейта нет (прозаический вход) — отчётная строка,
   промоция по D-0063 при рецидиве.
3. **Реанимация.** ID не меняется, новая запись не заводится. Тело
   возвращается VERBATIM, стаб исчезает; в архиве остаётся ровно
   строка `**РЕАНИМИРОВАНО <дата> → <канон-путь>.**`. I2 запрещает
   «тело и там и там». Повторное ретирование легально.
4. **Пустой вход.** Пустое тело секции в каноне — FAIL «форма не
   распознана», не тихий PASS. Заголовок архива без тела и без
   реанимации — FAIL. Стаб без указателя — FAIL. Не-UTF-8 архив —
   FAIL явным текстом.
5. Конфликт «короткий VS информативный» закрыт Б3(A)+I7.
6. Конфликт «I3 красен по чужому дефекту» закрыт Б5(A) — дыра
   закрыта до диспатча.
7. **Пин allowlist.** Закрыт запретом I5; перепин — акт Lead.
8. Лимиты спеки: 4/5 строк, 400/401 байт — тестируются оба края.
