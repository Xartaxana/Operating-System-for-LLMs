## §0. НЕСУЩИЙ ФАКТ МОЕГО БРИФА ОПРОВЕРГНУТ ЧТЕНИЕМ

Я написал: «все три ассерта символические, поэтому возврат порога вниз
ИЛИ вверх пройдёт с зелёным каноном». Три ассерта действительно
символические, но **число `37500` стоит ЛИТЕРАЛОМ ещё в четырёх
ожиданиях того же файла** — `tools/test_session_context.py:911, 930,
954, 969`, внутри ожидаемых строк бут-бюджета. `boot_budget_lines()`
собирает суффикс как `f"…{claude_size}/{CLAUDE_WARN}"` (`:1032`), значит
любая правка `CLAUDE_WARN` СЕГОДНЯ красит канон четырьмя тестами.

**Почему вывод по существу всё равно стоит:** это ровно те «пины текущих
чисел», про которые блокер брата вынес решающее наблюдение — их правит
любой подниматель как рутину, и они ничего не утверждают о норме.
**Точная формулировка: не «сторожа нет вовсе», а «сторож есть только в
форме, которую сегодняшний блокер признал недостаточной».**

## §1. ПОЧЕМУ КОНСТРУКЦИЯ ДРУГАЯ (а не копия брата)

| признак | гейт (а) | пороги ядра |
|---|---|---|
| носитель | список записей с провенансом | две голые константы |
| **база формулы** | **ОБЪЯВЛЕННОЕ число** `measured` | **ЖИВОЙ ФАЙЛ** — `stat().st_size` |
| коэффициент | K=1.05 полем записи | K=1.015 только в тексте комментария |
| кодовых путей | вердикт + ИТОГ + `--check-form` | ОДИН (`boot_budget_lines`); у BREACH — НОЛЬ |
| всплытие | пришлось заводить | УЖЕ ЕСТЬ: суффикс печатается каждым SessionStart |
| движение вниз | почти никогда | часто: четыре диеты подряд |

**РЕШАЮЩАЯ АСИММЕТРИЯ.** У брата сторож — аудитор ОБЪЯВЛЕННЫХ чисел,
поэтому весь его отказ про подделку объявления. Здесь база не
объявляется — **она измеряется**. Число, которое нельзя подделать,
нельзя и подогнать. Отсюда сторож МЕНЬШЕГО размера и с ЛУЧШИМИ зубами:
без истории, без блока `raised`, без поля «слово оператора», без калитки
аннулирования — потому что подделывать нечего.

**Что нельзя получить никакой конструкцией (проектный факт):**
состояние «порог поднят про запас» и состояние «файл похудел после
диеты» — для машины ОДНО И ТО ЖЕ состояние. Численно: при `WARN=37500` и
файле 36998 Б потолок 37600; просадка появится при размере 36847 Б.
**Диета в 151 байт сделала бы канон красным** — это цена жёсткого
варианта, и её надо знать до выбора.

## §2. НОРМА — ДОСЛОВНО

> **ХРАПОВИК ЯДРА.** `CLAUDE_WARN` — не константа проекта, а ФУНКЦИЯ
> ЗАМЕРА: `WARN = ceil(size(CLAUDE.md) × 1.015 / 100) × 100`, где `size` —
> размер файла на диске (тот же замер, что печатает суффикс SessionStart).
> **(1) СНИЖЕНИЕ ЛЕГАЛЬНО ВСЕГДА И МОЛЧА.** После диеты порог
> перевыводится тем же выражением: ни слова оператора, ни события. Снижать
> — бесплатно.
> **(2) ПОДЪЁМ ЛЕГАЛЕН, ТОЛЬКО ЕСЛИ ЕГО УЖЕ ОПЛАТИЛ ЗАМЕР.** Новый порог
> не выше потолка от РАЗМЕРА ФАЙЛА НА МОМЕНТ ПОДЪЁМА. Подъём про запас
> невозможен не по запрету, а по арифметике: чтобы поднять порог, надо
> СНАЧАЛА иметь байты. С пробитого 37500 следующий легальный потолок —
> 38100 (+600 Б), не больше.
> **(3) K = 1.015 — ЧАСТЬ НОРМЫ**, не параметр реализации. Другой K —
> смена правила вывода: отдельное решение оператора и отдельная правка
> литерального пина.
> **(4) СЛОВО ОПЕРАТОРА** дописывается в комментарий-провенанс
> ПРИСТРОЙКОЙ; прежние абзацы не переписываются. Молчаливый подъём —
> отказ механизма.
> **ПРОСАДКА** (WARN выше потолка) — не нарушение, а ДОЛГ: объявляет себя
> строкой в КАЖДОМ SessionStart, пока не снята перевыводом.

**Почему УЖЕ, чем «поднимается когда надо»:** зуб — пункт (2), и он
СТРОЖЕ, чем у брата. У брата «замер пробил порог» — ЗАПИСАННОЕ число,
которое подниматель пишет сам (честно названная дыра, подтверждённая
атакой 5). **Здесь пробой не записывается, а измеряется в момент
прогона.** Ни одно число нормы не под пером поднимателя, кроме самого
порога — а он сверяется с измеренным потолком.

## §3. ПРОВЕРКА ПРОТИВ ШЕСТИ АТАК БРАТА

| # | атака | применима? | чем закрыта |
|---|---|---|---|
| **1** | подъём в 3.4 раза при пробое +1 Б | **НЕ ПРИМЕНИМА ПО ПОСТРОЕНИЮ** | величина не задаётся человеком: потолок от `size`. Чтобы легализовать 525000, нужен файл ≈517 КБ — на бут-пути с лимитом 100000 Б, печатающем свой размер каждой сессии |
| **2** | порог от одного окна, пробой от другого (два ЧЕСТНЫХ замера) | **НЕ ПРИМЕНИМА ПО ПОСТРОЕНИЮ** | замер РОВНО ОДИН и безокновый. Второго честного числа не существует. **Главный выигрыш этой породы** |
| **4** | K=1.2 | **ПРИМЕНИМА** | двумя слоями: литеральный пин `CLAUDE_WARN_K_PERMILLE == 1015` + **таблица значений написана НЕЗАВИСИМЫМИ литералами**, а не вызовом с константой модуля. Прямой урок атаки 4: тест, берущий K из модуля, доказывает самосогласованность, а не норму |
| **5** | запись без полей → проверка отключается | **НЕ ПРИМЕНИМА** | необязательных полей нет: база из `stat()`, K — обязательная константа |
| **5б** | `measured=0` гасит проверку | **ИНВЕРТИРОВАНА ПО ЭФФЕКТУ** | нулевой замер не выключает проверку, а делает её МАКСИМАЛЬНО строгой: потолок 0, просадка = весь WARN. Пустой файл — не «нет данных», а «данные = 0» |
| **СБРОС** | калитка мимо цепочки | **НЕ ПРИМЕНИМА в исходной форме** (цепочки нет), но рождает аналог — снос самой проверки. Закрыта ЧАСТИЧНО: `session_context.py` в `MECHANISM_PREFIXES`. **НАЗВАННАЯ ДЫРА:** тестовые пути в невод НЕ входят (позитивный контроль формы приложен), удаление тестового модуля проходит коммит-гейт |

**Ответ на решающее наблюдение блокера:** тест легальности **не содержит
числа 37500 нигде** — он считает потолок от живого файла и сверяет
таблицу независимыми литералами. Подниматель, поправивший все пины, всё
равно упирается в потолок и во всплытие. Пины здесь несут другую работу:
доставить ТЕКСТ НОРМЫ тому, кто правит число.

## §4. КОД — ДОСЛОВНЫЕ ДО/ПОСЛЕ

### 4.1 `tools/session_context.py`, константы

Комментарий-провенанс НЕ переписывается — дописывается ПРИСТРОЙКОЙ
абзацем (форма существующих абзацев). Добавляются:

```python
CLAUDE_WARN_K_PERMILLE = 1015  # K = 1.015, в промилле: ЕДИНСТВЕННЫЙ
# носитель коэффициента; целые числа -- чтобы двоичное округление не
# двигало вердикт на точных кратных (пин: 20000 -> 20300, 40000 -> 40600).


def claude_warn_ceiling(size_bytes) -> int:
    """Потолок легального CLAUDE_WARN при данном размере CLAUDE.md.

    ceil(size * K / 100) * 100 в ЦЕЛОЙ арифметике. Отрицательный,
    None и нечисловой вход -> 0 (fail-closed: неизвестный размер даёт
    НУЛЕВОЙ потолок, т.е. максимальную строгость, а не отключение
    проверки -- прямой урок атаки 5б блокера t-569, где нулевой замер
    ГАСИЛ проверку формулы).
    """
    try:
        size = int(size_bytes)
    except (TypeError, ValueError):
        return 0
    if size <= 0:
        return 0
    return -(-size * CLAUDE_WARN_K_PERMILLE // 100000) * 100
```

Текст абзаца-пристройки несёт норму §2 целиком плюс строку:
`CLAUDE_BREACH кодового пути НЕ ИМЕЕТ СОЗНАТЕЛЬНО (решение Р2(iii)):
это объявленная сессиям верхняя граница, её вердикт выносит человек;
отношение WARN+300 пиновано.`

вход:* файла нет или `OSError` → missing, маркер не считается, строка
байт-в-байт; файл 0 байт → потолок 0, просадка максимальна; нечисловой
или отрицательный размер → 0 (fail-closed). *Конфликты собственных
требований:* (1) «маркер всегда при просадке» × «существующие тесты не
меняются» — побеждает первое, список изменяемых ЗАКРЫТ четырьмя; (2)
«сторож меряет живой файл» × «канон детерминирован» — побеждает
детерминизм: единственный живой тест СЕБЯ сверяет с пересчётом; (3)
«просадка = долг» × «сторож обязан иметь зубы» — побеждает первое
СОЗНАТЕЛЬНО, цена названа; (4) `CLAUDE.md` может измениться параллельным
диспатчем — ожидание привязано к ДИАПАЗОНУ, расхождение = доклад.
*Временной край:* до правки не существуют `CLAUDE_WARN_K_PERMILLE`,
`claude_warn_ceiling()`, маркер, модуль. Оба мира описаны. *Позиционный
край:* ветка ВНУТРИ `else` и ПОСЛЕ OVER. **Инвариант: мир missing и мир
«файл под порогом» печатаются БАЙТ В БАЙТ; текст и позиция
`OVER -> boot-diet (CLAUDE layer)` не меняются** (его цитируют
RULE_COVERAGE и boot-diet/SKILL.md); OVER и SAG взаимно исключены
(`ceiling(size) ≥ size×1.015 ≥ size`). *Порождающий край:* рождаются
константа K (носитель session_context, часть механизма), строка вывода
(носитель stdout SessionStart, владелец — оператор/калибровка), модуль
тестов (**в невод механизмов НЕ входит — названная дыра**), строка карты
(владелец — узел E), обязанность обновить строку оси 14.
