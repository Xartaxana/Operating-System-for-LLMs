# Реструктура бута — DAG (D-0080)

Заказ оператора 2026-08-18: бут раздулся (114937 / 100000, BREACH) и
ушёл от замысла. Замысел бута: держать в голове рабочей сессии ТОЛЬКО
то, что нужно КАЖДОЙ сессии, чтобы не забыть, о чём проект — идея,
архитектура, цели. Всё остальное (история/логи/таблицы/детальные
спеки/live-state) — REFERENCE по указателю. Если бут нуждается в
«лайт»-компаньоне, значит сам бут неправильный.

## Ключевое архитектурное решение (снимает вопрос оператора «как
заполнять очереди Boot Report, если вынести CURRENT_CONTEXT»)

Бут расслаивается на ДВА слоя (сейчас слиты):
- **Слой A — ОРИЕНТАЦИЯ** (стабильная: идея/архитектура/цели). ~8 КБ.
  Грузится ВСЕГДА, дёшево. Кандидат на авто-загрузку каждую сессию.
- **Слой B — СОСТОЯНИЕ/ПРОДОЛЖЕНИЕ** (CURRENT_CONTEXT). Остаётся
  ИСТОЧНИКОМ разделов Boot Report «очередь / следующая цель». Boot
  Report НЕ отменяется. Меняется только диета B: пункт очереди = строка-
  указатель (нерешённое + владелец полного текста, по правилу D-0038),
  не вложенный разбор. Разделы отчёта заполняются как раньше, из
  коротких пунктов; деталь пункта — по указателю.

«Лайт-бут» (SessionStart-хук: часы/модель/диспатчи/квота/проводка) —
это ЗАКОННЫЙ третий слой живых ЗАМЕРОВ, которые в статичном документе
жить не могут. Он не костыль; костыль был в том, что к ориентации
подмешали референс и live-state.

Замер (wc, 2026-08-18): 11 файлов бута = 79047 Б; из них big-3
(CURRENT_CONTEXT 37533, DECISIONS 19954 — эти в 11; CLAUDE 35890 —
авто-грузится, вне 11) = 81% бюджета. Девять «ориентационных» = ~11 КБ.
Разведка содержимого — t-478 (принята по трейлу). Дубль-карта: «git =
source of truth» 7× в 6 файлах; SYSTEM_PROMPT весь дублирует
PHILOSOPHY/CHARTER/CLAUDE.md (R9); ROADMAP хвост = CURRENT_CONTEXT
L15-17.

обязательную ориентацию не жалко грузить всегда) и снимает D-0038.

## Решения оператора (2026-08-18, зафиксированы)

1. **Полный Boot Report авто** на свежем старте (ориентация + состояние +
   очередь + следующая цель + STOP). source-гейт: не на compact/resume.
2. **Бюджет = Слой A + Слой B + CLAUDE.md** — меряем ОБА слоя (плюс
   CLAUDE), т.к. оба попадают в контекст при начале работы. Референс-
   файлы (DECISIONS_FULL, DELEGATION_TABLE, ROADMAP-архив) и per-item
   подробности в бюджет НЕ входят (по запросу).
3. **Диета CURRENT_CONTEXT — на усмотрение Lead, критерий: не разрастается
   + остаётся полезным.** Механизм (слово оператора): подробность по
   пунктам очереди выносится, подтягивается ТОЛЬКО для ВЫБРАННОГО пункта,
   когда оператор его выбрал — не все сразу. CURRENT_CONTEXT держит
   короткую строку-указатель на пункт + владельца подробности.
   РЕАЛИЗАЦИЯ (F9, критик t-479): владелец подробности = существующий
   docs/tasks/ DAG (D-0080), НЕ новый класс файла — то же поведение без
   orphan-on-close/drift.
4. **CLAUDE.md — диета В ЭТОТ ЖЕ заход** (не следующим рычагом).
5. **ТРИ ДИЕТЫ** (слово оператора): Слой A, Слой B, CLAUDE.md — три
   разных режима разрастания. Skill бут-диеты обновить так, чтобы при
   пробое СУММАРНОГО бюджета (A+B+CLAUDE) запускались ВСЕ ТРИ.
