## §1. МЕХАНИКА: что переносится из формы чеков, а что нет

Форма чеков (`body`/`bodypred` + пре-пасс) переносится **НЕ целиком**:
переносится ядро+тело+указатель+машинная сверка пары; **НЕ переносится
предикат живости в окне.** У карты нет окна и нет вопроса «живо ли это
сегодня» — её вопрос «что стережёт вот эту норму», и он не имеет
временного среза. Тело читается **по нужде читателя**, а не по вердикту
прогона; вся защита переезжает в правило достаточности §2 плюс машинную
разрешимость указателя §4.

Экономия берётся не со всех 61 строки, а с **пяти самых плотных строк и
одной статьи справочника** — диффа касается 6 мест вместо 61.

## §2. ГЛАВНЫЙ РИСК И ПРАВИЛО ДОСТАТОЧНОСТИ

**Риск назван прямо: тело, в которое никто не заглянет, ХУЖЕ длинной
строки — длинная строка честна.** Против него стоит не байтовый
критерий, а критерий ДОСТАТОЧНОСТИ ОТВЕТА БЕЗ ОТКРЫТИЯ ТЕЛА.

Строка, получившая тело, обязана нести ЧЕТЫРЕ элемента. Отсутствие
любого = вынос сделан неверно, дефект приёмки, а не мелочь стиля:

1. **НОРМА** — идентификатор (`R…`/`D-…`/`F-…`/названное решение) и одно
   предложение обязанности: что запрещено или предписано.
2. **РЕЖИМ** — слово(а) легенды. **Колонка режима не выносится НИКОГДА и
   ни в какой части** — это ответ на вопрос «что со мной будет».
3. **НОСИТЕЛЬ** — резолвимый указатель на сторожа: путь файла И имя
   символа/теста, либо `чек N` строчными.
4. **ФЛАГ ОГРАНИЧЕНИЯ** — если у сторожа есть ПРИНЯТАЯ ДЫРА, ИЗВЕСТНОЕ
   ОГРАНИЧЕНИЕ или отсутствующий детектор отказа, ФАКТ этого остаётся в
   ядре одной формулой. **Выносится только РАЗБОР дыры, никогда её
   существование.**

**Законно уходит в тело:** история и провенанс (даты, номера задач,
прежние редакции), рационал и цена решения, замеры и проценты,
перечисление внутренних подветок разбора, прецеденты, контрпримеры,
таксономии, «почему приняли именно так».

**Запрет:** ужимать ценой несущего факта нельзя. Если строка не
выносится без потери — **это законный итог**: строка остаётся длинной,
исполнитель пишет об этом отдельным пунктом отчёта.

## §3. ФОРМА ВЫНОСА

Ядро строки заканчивается указателем ВНУТРИ той же ячейки:
```
Развёртка (<что именно там>) — тело: docs/rule_coverage/RC-01.md#<якорь>
```
Тело — `docs/rule_coverage/RC-0N.md`, ОДИН файл на СЕКЦИЮ карты, по
образцу `PROCESS/checks/CHK-*.md`: шапка с `ВЛАДЕЛЕЦ`, `ОБРАТНАЯ ССЫЛКА`,
`ПРАВИЛО ВЕДЕНИЯ`, затем секции `## <якорь>`.

**Второй способ выноса, предпочтительный где применим:** у детали УЖЕ
ЕСТЬ владелец (`docs/FINDINGS.md`, `docs/DECISIONS_FULL.md`,
`docs/SIBLING_MAP.md`) — тогда новый файл не заводится, указатель ведёт
туда. Это снижает дублирование («одна норма — один дом») и заодно риск
протухания.

**Якорь строки** — новая сущность: вводится ТОЛЬКО у строк с телом,
форма `rc<секция>-<ключ>` строчными, уникальность проверяется машинно.

## §4. МАШИННЫЙ СЛОЙ — `tools/test_rule_coverage_bodies.py` в каноне

Каждый ключ — с позитивной И негативной синтетикой в `tmp_path`:

- **K1 указатель→файл:** каждый указатель резолвится в существующий файл.
- **K2 сирота:** каждый `docs/rule_coverage/*.md` сослан РОВНО одной
  строкой (образец — `PAIR: файл-сирота` пре-пасса).
- **K3 якорь:** якорь указателя существует в теле; якоря уникальны.
- **K4 форма тела:** маркеры шапки; UTF-8, LF, без BOM.
- **K5 «чек N» в телах резолвится** — БЕЗ правки чужого носителя:
  `from calibration_prepass import load_protocol_structure,
  validate_rules_backward` (обе функции публичны) и прогон на тексте
  тела. **Так обратная сверка, которую вынос иначе бы ПОТЕРЯЛ,
  восстанавливается.**
- **K6 достаточность-минимум (форма, не смысл):** у строки С УКАЗАТЕЛЕМ
  колонка режима непуста и содержит слово легенды, а третья колонка
  содержит хотя бы один резолвимый носитель. Смысл судит приёмка.
- **K7 молчаливый ноль запрещён:** распознано 0 строк или 0 указателей
  при непустом каталоге тел → тест ПАДАЕТ, а не «зелёный, потому что
  проверять нечего».

**Адверсариальная батарея** (синтетика, не боевой файл): битый
указатель; сирота; дубль якоря; пустое тело; BOM; CRLF; `чек 99` в теле;
указатель ВНУТРИ ```-фенса карты (не должен засчитываться — иначе фенс
«усыновляет» сироту).

**Не дублируется сознательно:** сверка `rules:RC§N/token` шапок протокола
уже держится `--check-form` в каноне.

## §5. АРИФМЕТИКА ЦЕЛИ И ЗАМЕР

`bpr = int(round(bytes/records))`; `bpr ≤ 1005 → OK`; `≤ 1058 → WARN`;
иначе BREACH. При неизменных `records=61`:

| цель | требуемые bytes | вынести не менее |
|---|---|---|
| выйти из BREACH в WARN | ≤ 64 538 | 7 339 Б |
| попасть в **OK** | ≤ 61 300 | **10 577 Б** |

**Целевая полоса — OK, не WARN.** Карта пришла в BREACH из WARN за один
день; сдача в WARN гарантирует повторный пробой на первой же норме, и
работа делается второй раз.

**ЗАМЕР Lead (ответ на запрос драфтера; у него не было Bash):** длины
строк-записей, топ:

```
3110 Б — строка 66      2338 Б — строка 64
2998 Б — строка 61      1607 Б — строка 62
2947 Б — строка 96      1591 Б — строка 56
2835 Б — строка 122     1514 Б — строка 103
статья справочника «чек 26» (199-232) = 3529 Б
```
Сумма пяти верхних строк = **14 228 Б**, плюс справочник 3529 Б.
Потребность 10 577 Б покрывается с запасом. **Кандидатский набор
драфтера (61, 64, 66, 96, 122 + справочник) подтверждён замером почти
дословно** — его оценка по объёму текста оказалась верной.

## §6. УЧЁТ БАЙТ

**Принят вариант (A):** каждое тело — ОТДЕЛЬНАЯ запись
`tools/corpus_manifest.json`, ровно как уже сделано у трёх тел чеков:
```json
{ "path": "docs/rule_coverage/RC-01.md", "unit": "развёртка строки",
  "record_re": "^## rc\\d+-", "owner": "corpus", "bpr_max": <по замеру ×1.15> }
```
Порог продолжает мерить ПЛОТНОСТЬ ЯДРА — ровно то, ради чего заведён.

**Вариант (C) — тела вне манифеста — ОТВЕРГНУТ ЯВНО:** байты уходят
из-под надзора корпуса, экономия становится фиктивной, а блок «ВЫБЫЛИ»
не сработает (путь никогда не был в манифесте). Это тот самый класс
«диета-удалением», против которого корпус и заведён.

Сумма корпуса не меняется — вынос есть перемещение, и это ПРАВИЛЬНО:
цель хода — плотность ядра, а не сжатие корпуса.

## §7. ПОРОГ `bpr_max` ПОСЛЕ ВЫНОСА — ОСТАЁТСЯ 1058

Наблюдение драфтера, принято: **перевывод по формуле ×1.15 от нового
замера даёт ПОДЪЁМ, а не приведение.** Новый bpr ≈ 1000 →
`ceil(1000×1.15) = 1150 > 1058`. По классу решения Р-D (подъём легален
только словом оператора И замером, ПРОБИВШИМ прежний порог) такой
перевывод **нелегален по собственной норме**: замер после выноса порог
не пробивает. Оставить 1058 — не консерватизм, а единственный вариант,
не требующий слова оператора.

  `corpus_manifest.json`, ни `corpus_growth.py` НЕ входят в

  без осевого блока** — при том что порог, выведенный формулой от
  замера, буквально предмет оси 14. Второй слой: у corpus-порогов нет
  храповика-аналога, подъём `bpr_max` ничем не отличается от снижения.
- **Н4 ПРИНЯТА к сведению.** Справочник чеков не нумерован, поэтому для
  резолвера принадлежит СЕКЦИИ 7. Сегодня безвредно, но резолюция могла
  бы «позеленеть» по справочнику, а не по норме. Прямое ограничение на
  вынос справочника: И-1 обязателен.
- **Н5 ПРИНЯТА, в очередь как КЛАСС — и она объясняет вчерашнюю
  опровергнутую находку.** Для двух строк `mechanism_gate.py` инструмент
  Grep показал `"tools\md_regions.py"` и `endswith("\")`, тогда как Read
  того же файла показывает `"tools/md_regions.py"` и `endswith("/")`.
  Read совпадает с моим замером, опровергшим находку 8.1 прошлого
  драфта, — то есть у той находки, вероятно, ровно этот источник:
  **прямой слеш отрендерился в выводе поисковика обратным.** Правило
  класса: **посимвольные утверждения (слеш, кавычка, экранирование)
  валидны только по Read, не по выводу поисковика.** Сам факт рендеринга
  требует отдельной проверки прежде, чем станет нормой.
