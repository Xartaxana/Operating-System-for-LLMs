## Контекст решения «не Langfuse» (вердикт Lead 08-13, второй проход D-0066)

ради одного оператора; их Claude-Code-плагин — Stop-hook на внутренностях

произвольным metadata — спорная зона (открытые issues против доки).

Langfuse не принимает вовсе (только трейсы) — а официальный разрез
скилл/агент Claude Code живёт именно в OTel-метриках
(claude_code.token.usage / cost.usage: agent.name, skill.name, model,
query_source, session.id, USD по листовым ценам; работает на подписке —
сверено Lead по code.claude.com/docs/en/monitoring-usage.md 08-13).
Формат сырых JSONL-транскриптов официально нестабилен (sessions.md) —
транскрипты остаются ретроактивным источником истины, OTel — возможная
надстройка (развилка (в)).

## 0. Рамка, принципы, самопроверка Rule #1

**Р0.1. Ноль LLM в петле.** Всё в разделах 1–5 — детерминированный
Python+SQL поверх gateway/requests.db и logs/routing-log.jsonl.
Нарратив — отдельный ход человека/Lead поверх готовых чисел.

**Р0.2. Ноль новых носителей, где хватает существующих (D-0030).**
Производные таблицы — в ТУ ЖЕ gateway/requests.db (CREATE TABLE IF NOT
EXISTS); cc_usage и requests на запись НЕ трогаются НИКОГДА. Журнал
остаётся append-only jsonl. Импорт транскриптов переиспользует

**Р0.3. Знаменатели ВЫВОДЯТСЯ, а не ДЕКЛАРИРУЮТСЯ, где возможно.**
Каждый декларируемый знаменатель = новая обязанность будущих сессий =
механизм с детектором отказа (R10в). В v1 — ноль новых обязанностей,
кроме одной строки в существующем чеке 18 калибровки (раздел 2).

**Р0.4. Rule #1 к самому мониторингу.** Разовая цена: 4
builder-диспатча + 1 док-узел. Периодическая: один прогон скрипта на
калибровку + идемпотентный импорт при прогоне отчёта (время импорта
ИЗМЕРЯЕТСЯ в DoD B1, край E11). Что находит: калибровка №6 уже руками
считала «$472.79/день, $/принятую $5.48, сайдчейны $789.35 против main
$1527.29 = 34%» — эти числа добываются сейчас руками Lead-яруса;
автоматизация окупается первым прогоном. Что НЕ строим: OTel-приёмник
(развилка в), атрибуция main-chain по-ходово (развилка а), Langfuse.

**Р0.5. Ось 2 SIBLING_MAP («учёт честен на обоих контурах»)
обязательна.** Подкласс F-38: requests.prompt_tokens ВКЛЮЧАЕТ
кэш-колонки, cc_usage.input_tokens ДИЗЪЮНКТЕН им — формулы между

## 1. ОПРЕДЕЛЕНИЯ МЕТРИК (Q1–Q4)

### Базовые операции

**O1. Ключ связи «стадия → деньги».** stage = каждая строка
journal.event="delegated" (включая критик-вход, ретраи attempt≥2,
replaces_worker), упорядочено по (ts, позиция в файле).
stage_cost_usd(stage) = SUM(cc_usage.accounted_cost_usd) WHERE
cc_usage.agent_id = norm(journal.worker_ref) AND cc_usage.project =
:project; stage_turns и stage_unpriced_turns — тем же фильтром.
norm(x) — снять префикс `agent:` у журнала и (если нужно) `agent-` у
cc_usage.agent_id. ТОЧНАЯ форма равенства НЕ СВЕРЕНА дизайнером
(read-only) — первый приёмочный ключ B1 с позитивным контролем; формы
не совпали ни при одной из двух нормализаций → ВОПРОС наверх (R11a).

**O2. Окна.** Окно = интервал между соседними journal.event="calibrated"
(сейчас 6; контроль формы: dispatch_skipped=93). Границы — из поля ts;
прозаические границы из notes НЕ парсятся. Первое окно — partial=1.
Переопределение — --window-start/--window-end (ISO local naive).

**O3. Стоимость никогда не молчит.** Агрегат возвращает (value,
unpriced_turns, models_without_price); при unpriced>0 печать
`>= $X (N ходов без цены: <модели>)`. Форма-эталон —
token_usage_stats.py («н/д (нет цены: %s)»).

### Q1 — Переключения

По задаче T: stages(T) = число delegated; rework_stages(T) = delegated
ПОСЛЕ первого rejected (replaces_worker НЕ реворк; классификация веток
зеркалит calibration_counts.py:337-396); critic_entries(T);
task_cost(T) = Σ stage_cost; accepted(T) — существование accepted.

- **M1 переключений/принятую** = Σ stages / Σ accepted (падает =
  переключений меньше). Знаменатель: принятые задачи окна.
- **M2 $/переключение** = Σ task_cost / Σ stages.
- **M3 доля переделки** = Σ cost стадий после первого rejected / Σ task_cost.
- **M4 доля координатора за окно** = SUM(cost WHERE is_sidechain=0) /
  SUM(cost) по окну+проекту. БЕЗ атрибуции задачам (развилка а).
  Первая точка ряда: №6 → ≈0.66.
- **M5 топ-N задач по стоимости** с колонками stages / rework /
  critic_entries / cost / accepted — вход детектора.

### Q2 — Скиллы

Скиллов пять (next-task, permission-audit, session-handoff,
kit-release, boot-diet), у каждого нумерованные шаги SKILL.md =
естественные фазы. НЕСУЩЕЕ ОГРАНИЧЕНИЕ: приватностный контракт
usage_report.py:11-14 («never reads message content, tool
inputs/outputs, or any prompt text») закрывает добычу скилла из
tool_use-входов транскрипта НОРМОЙ, не сложностью → развилка (б).

- **M6 стоимость прогона** = Σ cost строк сессии в [ts_start, ts_end)
  прогона из реестра (run_units).
- **M7 доля фазы** = Σ cost строк фазы / M6; без меток — `н/д (нет
  фазовых меток)`, молчаливого нуля нет.
- **M8 $/единицу работы скилла** = M6 / unit_count (boot-diet → байты
  boot-пути ДО; permission-audit → число разобранных вызовов;
  kit-release → синк-пары parity_manifest; session-handoff → пункты).
  Все четыре ВЫВОДИМЫ.

### Q3 — Нормировка

- **M9 $/журнальное событие окна** (calibration_counts --json →
  in_window_count).
- **M10 $/принятую по ярусам** (механизация метрики Архитектора §3 и
  чека 18(в)) = Σ stage_cost стадий agent=tier / count(accepted яруса).
- **M11 $/строку диффа ревью** = Σ cost critic-стадий / Σ added+deleted
  (git diff --numstat по окну).
- **M12 $/чек калибровки** = стоимость калибрующей сессии / число
  чеков протокола (греп `^\d+\. \*\*`, сейчас 33).
- **M13 $/ход разведки (ПРОКСИ)** = Σ cost scout-стадий / Σ turns;
  помечается ПРОКСИ (байты чтения недоступны без нарушения контракта
  или новой обязанности — не вводить).
- **M14 эскалационная цена** (механизация чека 21) = Σ task_cost задач
  с escalated / count(escalated); рядом контрфакт
  savings_report.fable_counterfactual.

### Q4 — Детект

sinks = [(сток, $ окна, дельта, флаг)] по убыванию $; тренды — ряд
window_series за K окон (↑/↓/=).

## 3. ХРАНИЛИЩЕ

Всё в gateway/requests.db, только новые таблицы (CREATE TABLE IF NOT
EXISTS); перестроение DELETE+INSERT одной транзакцией; тест байтового
равенства двух подряд перестроений; инвариант-охранник: COUNT(*) и

- **task_stage_costs**: task_id, stage_index, journal_line, ts_local,
  agent, model_declared, worker_ref, agent_key (norm; NULL для

  ни одной ценённой строки), unpriced_turns, models_measured,
  stage_kind (first|retry|critic|replacement|other), measurable (0
  если worker_ref не agent:<id>). PK (task_id, stage_index).
- **task_costs**: task_id PK, first_delegated_ts, last_event_ts,
  window_id (окно ПЕРВОГО delegated), category, stages, rework_stages,
  critic_entries, rejected_count, escalated_count, accepted 0/1,
  open_at_window_end 0/1, self_exec 0/1 (0 измеримых стадий),
  cost_usd, unpriced_turns, turns.
- **run_units**: run_id, run_kind (skill|calibration|exam|window),
  name, phase (NULL = уровень прогона), ts_start, ts_end, session_id,
  unit_kind, unit_count, source. PK (run_id, phase).
- **window_series**: window_id, window_start, window_end, partial,

  denominator_kind ('absolute' для абсолютных), denominator_value,
  unpriced_turns, reason (почему NULL), computed_at.
  PK (window_id, metric_key).
