# Спека узла I — `tools/warn_density.py` (измеритель доли срабатываний warn-слоёв)

**Происхождение:** дизайнер-диспатч t-574, 2026-08-20. Слово оператора:
первым в очереди, раньше любых новых гейтов. **Статус:** ДРАФТ ПРИНЯТ
Lead, девять развилок закрыты (§R), пять запросов факта — часть отвечена,
часть требует зонда (§ЗФ). Персистирован — жил только в транскрипте (F-50).

**Зачем:** находка F10 калибровки №8 опубликовала доли 82/77/60%, которые
оказались завышены. Механика ошибки: считались **имена слоёв** (живущие в
исходниках, тестах, отчётах, спеках), а не срабатывания; и каждое
срабатывание оставляет в транскрипте минимум ДВА следа. Исправленные
числа по телам: 92/65/156 — другой порядок величин.

## §1. ЯДРО: что считается срабатыванием (машинно)

**Срабатывание = факт, что слой напечатал свой текст в ОДНОМ вызове
хука.** Пара (единица вызова, слой), для которой выполнены ВСЕ условия:

1. Запись транскрипта имеет **СТРУКТУРНОЕ** поле
   `attachment.type == "hook_success"` — не подстроку в тексте. Ключ
   `"stdout"` встречается и у результатов Bash (измерено), поэтому разбор
   ТОЛЬКО через `json.loads` строки и путь `attachment.stdout`, **никогда
   грепом по сырому тексту**.
2. В `attachment.stdout` (сырой stdout хука — JSON, экранированный внутрь
   строки) ПОСЛЕ декодирования вложенного JSON найден зарегистрированный
   литерал слоя в поле `hookSpecificOutput.additionalContext`.
3. Единица вызова = `(attachment.toolUseID, attachment.hookName)`; при
   отсутствии `toolUseID` (SessionStart-класс) ключ — `uuid` записи.

**Чем срабатывание НЕ является** (перечислением — именно это дало F10):
вхождение имени в теле сообщения ассистента или пользователя; вхождение
в `toolUseResult`/`tool_result` (чтение исходника хука, греп по репо,
ручной прогон хука из Bash) — это ВЫВОД ИНСТРУМЕНТА; вхождение в
`<session>/tool-results/*.txt`; запись `attachment.type ==
"hook_additional_context"` — ВТОРОЙ след ТОГО ЖЕ срабатывания (измерено
на паре строк одного файла).

**Прямое следствие:** имя слоя из исходника, теста или отчёта физически
не может попасть в `attachment.stdout` записи `hook_success` — оно живёт
в другом структурном месте. Класс F10 закрыт ПО ПОСТРОЕНИЮ, а не
фильтрацией.

**Кратность.** Один вызов законно печатает НЕСКОЛЬКО слоёв в одном JSON
(`dispatch_gate:508` — «ДВА WARN В ОДНОМ ВЫЗОВЕ — ОДИН JSON-ОБЪЕКТ»;
`journal_echo:767` — семь слоёв через `"; "`), и один слой законно
печатает несколько строк. Считаются ДВА числа: `calls` (вызовов,
помеченных слоем — бинарно) и `lines` (отдельных строк слоя). Доля — от
`calls`.

## §2. ИСТОЧНИК И ЕГО ГРАНИЦЫ

**Источник:** транскрипты сессий JSONL. Обоснование: **другого носителя
следа срабатывания в репозитории НЕТ** — измерено чтением
`.claude/settings.json` (12 хуков) и содержимого `logs/` (семь файлов,
ни одного «слой напечатал X»); `logs/owns_registry.jsonl` пишет не о
своих WARN, а о пишущих диспатчах; `gate_log` в `logs/` отсутствует
(позитивный контроль формы негатива: тот же Glob вернул семь других имён).

**Границы — печатаются строкой в выводе:**
1. **`hookName` не различает скрипты на одном матчере.** На
   `PreToolUse:Task|Agent` зарегистрированы ТРИ скрипта, а имя записи
   одно. Различение возможно ТОЛЬКО по литералу — реестр §4 несёт
   несущую функцию, не удобство.
2. **Тишина хука, возможно, не оставляет следа.** Измеренное
   противоречие: в одном файле молчаливые `PreToolUse:Bash` записаны с
   `"stdout":""` (20 строк); в другом при 8 вызовах инструментов-матчеров
   записей `hook_success` всего 3. **Значит число вызовов хука нельзя
   брать из записей хука** — знаменатель строится от вызовов инструментов.
   Причина асимметрии — ЗФ-1.
3. **Возможная обрезка длинного stdout** — не проверена (ЗФ-3). До
   проверки инструмент печатает диагностику: сколько записей имеют
   `stdout`, не парсящийся как JSON целиком.
4. **Субагентские транскрипты** существуют отдельными файлами;
   дублируются ли по `toolUseID` — ЗФ-2. Дедуп §3 устроен так, что ответ
   на ЗФ-2 не меняет чисел.
5. **Только этот деплой** — строка «деплой: OS, чужие не измерены».
6. **Транскрипт не вечен** — число прочитанных файлов и байт печатается
   каждым прогоном (сравнимость окон).

## §3. ЗАЩИТА ОТ ДВОЙНОГО СЧЁТА — механика, не обещание

1. **Структурный фильтр:** считается только `hook_success`;
   `hook_additional_context` игнорируется ЦЕЛИКОМ. Дубль снимается в
   корне, а не вычитанием.
2. **Множество ключей** `seen: set[(toolUseID|uuid, hookName, layer_id)]`
   — глобальное по всему корпусу, не по файлу. Поэтому дубль
   «родительский транскрипт + субагентский файл» снимается автоматически
   при любом ответе на ЗФ-2, и его размер виден числом `dedup_dropped`,
   которое ПЕЧАТАЕТСЯ.
3. **Один слой — один литерал-владелец.** Два разных литерала в одном
   `additionalContext` — ДВА слоя (законно). Один литерал дважды —
   `lines += 2`, `calls += 1`.
4. **Перекрытие литералов ЗАПРЕЩЕНО формой реестра:** `--check` краснеет,
   если один литерал — подстрока другого (иначе `WITNESS ECHO` и
   `WITNESS ECHO STALENESS` посчитаются друг за друга).
5. Каждый прогон печатает `дедуп: снято N записей-дублей (из M)`.

## §4. РЕЕСТР ЛИТЕРАЛОВ — парная сущность

**Носитель:** `tools/warn_layers.json` (форма `corpus_manifest.json`).
Запись: `id`, `name`, `carrier`, `symbol|null`, `literal`, `aliases`,
`hook_event`, `matcher`, `denominator`, `listed_in_check_11v`.

**Классификация (R11(p)):** реестр — ПАРНАЯ сущность к перечню слоёв
чека 11(в) ⇒ **ось 4 SIBLING_MAP**, строка заводится Lead тем же
коммитом; владелец — калибрующий Lead; путь механизменный.

**Три слоя анти-протухания, все в одном `--check`:**
- **(i) живость литерала:** литерал ОБЯЗАН находиться в файле `carrier`
  (чтением, не памятью). Не найден → `ДЕФЕКТ РЕЕСТРА` + exit 1. Это
  ровно тот отказ, который в калибровке №8 дал молчаливый ноль.
- **(ii) привязка к константе, где она есть.** ИЗМЕРЕННЫЙ ФАКТ: не у
  всех слоёв есть константа — `journal_echo` собирает строки f-строками
  внутри функций, поэтому `symbol` ОБЯЗАН допускать `null`, а (i) обязан
  работать для всех. Единая import-привязка технически невозможна —
  свойство носителя, не выбор.
- **(iii) сверка с чеком:** печатаются ДВЕ разности — «в чеке названо, в
  реестре нет» и «в реестре есть, в чеке не названо». Вторая по словам
  самого чека («ПЕРЕЧЕНЬ ОТКРЫТ») печатается как НАХОДКА, не дефект.
- **`aliases`** хранят исторические литералы: старые транскрипты несут

## §5. ЗНАМЕНАТЕЛЬ

Абсолютные числа (`calls`, `lines`) печатаются ВСЕГДА и от развилки не
зависят. Кандидаты знаменателя: **Z1** вызовы своего хука (= вызовы
инструментов из матчера слоя); **Z2** диспатчи (`Task`/`Agent`); **Z3**
журнальные события окна; **Z4** все вызовы хуков окна; **Z5** сессии.

**Правила безопасности (норма, не развилка):** знаменатель 0 → печатается
`доля: н-д (знаменатель 0)`, НИКОГДА `0%` и никогда деления;
знаменатель-прокси помечается словом `proxy` в той же строке — иначе
рецидив F10, где прокси-база стояла в таблице рядом с честными.

## §6. КРАЯ (двенадцать, поведение названо на каждом)

1. **Пустое окно:** `ОКНО ПУСТО: 0 записей`, по слою `calls=0`, доля
   `н-д`; фикстура-контроль всё равно печатается; exit 0. `0%` запрещён.
2. **Слой с нулём при непустом окне:** строка в секции «НЕ СРАБОТАЛИ» с
   вердиктом по живости литерала. **Ноль без вердикта — дефект инструмента.**
3. **Источник отсутствует:** exit 2. Отличие от «каталог есть, файлов 0»:
   последнее — `ИСТОЧНИК ПУСТ`, exit 0 + дефект в `--check`.
4. **Битая строка JSONL:** пропуск + счётчик. **100% битых — НЕ «ноль
   срабатываний», а `ДЕФЕКТ ИСТОЧНИКА` + exit 1 у `--check`** (граница
   все/не все, тест на обеих сторонах).
5. **Сайдкар отсутствует** (первый прогон): `база: БАЗЫ НЕТ`, файл
   создаётся. **Не записался** (OSError): WARN, exit 0 — прогон состоялся.
6. **Запись без `timestamp`:** корзина `без времени: N`, в оконный счёт
   не входит; число печатается всегда (иначе тихая потеря).
7. **Запись без `toolUseID`:** ключ — `uuid`; нет и его — считается с
   пометкой `key=fallback:line`, число печатается.
8. **`stdout` не парсится как JSON:** литерал ищется по СЫРОЙ строке как
   fallback, запись помечается `raw-match`, число печатается отдельно —
   обрезка становится видимой, а не превращается в ноль.
9. **Конфликт собственных требований:** §1 требует структурного поля,
   край 8 разрешает сырое совпадение. Приоритет: структурный разбор
   ВСЕГДА первый; сырой fallback — ТОЛЬКО когда `json.loads` упал, и его
   результаты идут в ОТДЕЛЬНЫЙ счётчик.
10. **Второй конфликт:** реестр объявляет мёртвый литерал, И он же даёт
    срабатывания в старых транскриптах. Срабатывания считаются (по
    алиасу), дефект реестра ВСЁ РАВНО печатается — счёт и живость
    независимы.
11. **Один литерал — два носителя:** не дефект, `carrier` — список;
    пустой список — дефект формы.
12. **Часы:** транскрипт UTC-`Z`, журнал — локальное наивное время. Шапка
    печатает ОБА представления границ окна.

**Лимиты — тест НА границе и ЗА ней (оба обязательны):** окно
`[start, end)` — ts ровно `start` ВХОДИТ, ровно `end` НЕ входит; «все
строки биты» — N-1 из N → прогон, N из N → дефект; знаменатель 1/calls 1
→ `100.0%`, знаменатель 0 → `н-д`; пересечение литералов → `--check`
exit 1; кратность 1 строка → calls 1/lines 1, 5 строк → calls 1/lines 5.

**Адверсариальная батарея (R11(e)):** невалидный ISO → exit 2 без
трейсбека; start позже end → exit 2; `--transcripts` на ФАЙЛ → exit 2;
путь с пробелами и кириллицей; BOM и CRLF; строка в мегабайты (потоковое
чтение); вложенные экранированные кавычки и `—` (есть в реальных
литералах owns_gate) — литерал находится ПОСЛЕ декодирования; пустой
реестр → `--check` exit 1, обычный прогон печатает «слоёв 0» и не делает
вид, что измерил; дублирующийся `id` → exit 1; `{` в литерале (шаблон
формата попал целиком) → требование статического префикса, exit 1;
не-UTF8 консоль → `reconfigure(errors="replace")`.

## §7. ФОРМА (порода corpus_growth / calibration_prepass)

```
python tools/warn_density.py [--window-start ISO] [--window-end ISO]
    [--registry-file PATH] [--transcripts DIR] [--journal PATH]
    [--sidecar PATH] [--json]
python tools/warn_density.py --check [--registry-file PATH]
```
Секции вывода: `=== КОНТРОЛЬ ИСТОЧНИКОВ ===` (каталог, файлы/байты, окно,
**встроенная фикстура с известным числом срабатываний — печатается как
`фикстура K/K` и ОБЯЗАНА МОЧЬ УПАСТЬ**: содержит и позитив, и заведомо
непопадающее вхождение имени слоя в теле сообщения, которое считаться НЕ
должно; живость реестра; `дедуп: снято N`) → `=== СЛОИ ===` (id, calls,
lines, знаменатель, доля, статус) → `=== НЕ СРАБОТАЛИ ===` (каждый с
вердиктом) → `=== ДЕФЕКТЫ ===` / `=== НАХОДКИ О ЧЕКЕ ===` → `ИТОГ:`.

Сайдкар `logs/warn_density.jsonl`, одна JSON-строка на боевой прогон.
`--check` сайдкар НЕ пишет (прецедент O2). Коды: `0` прогон состоялся
(даже при высоких долях — измеритель, не гейт); `1` только у `--check`
при дефектах; `2` измерить нечего.

## §8. ЧЕТЫРЕ ВОПРОСА ПРАВИЛА 10

**(а) Цена.** Калибрующий Lead — один прогон за калибровку и строка чисел
в notes; автор слоя — ОДНА строка реестра при заведении и правка при
переименовании (сигнал приходит КРАСНЫМ `--check` в каноне, а не
проверкой памяти); билдер — разовая постройка. Цена сознательно НЕ
включает блокировку: инструмент не гейт, exit 0 при любых долях (порог
доли норма запрещает назначать заранее).

**(б) Оси перечислением (карта на 14 осей):** 1 н-п (измеряет носители
ЭТОГО деплоя); 2 н-п; 3 н-п; **4 ПОКРЫТА** (реестр ↔ перечень чека
11(в), строка Lead тем же коммитом); **5 ПОКРЫТА** (тесты в каноне);
6 н-п; 7 н-п (в публичный шаблон не выносится; иначе — в очередь);
8 н-п; **9 ПОКРЫТА** (сайдкар переживает сессию); 10 н-п; 11 в очередь;
12 н-п (ROLE-TYPE меряется, привязка не трогается); 13 н-п (только
читает, единственная запись — свой сайдкар); **14 н-п ОСОЗНАННО** —
порог доли не вводится; если Lead когда-нибудь введёт, ось 14 становится
обязательной (записано, чтобы будущий порог не проскочил мимо неё).
Режимы отказа: «молчаливый ноль счётчика» ПОКРЫТ (фикстура, способная
упасть; ноль всегда с вердиктом); «читает только собственный след»
покрыт частично, ОСТАТОК НАЗВАН — смерть ПРОВОДКИ хука инструментом не
ловится (это чек 26(а)/`wiring_check`), и низкая доля при мёртвой
проводке будет выглядеть как тишина: строка об этом печатается;
«не отличает утверждение от цитируемого» ПОКРЫТ структурным фильтром §1.

**(в) Детектор собственного отказа — четыре, все машинные:** фикстура в
каждом прогоне, обязанная МОЧЬ упасть (тест на её падение); `--check`
живости литералов (краснеет ровно в том мире, где инструмент ослеп);
`test_warn_density.py` в каноне; регистрация в шапке чека 11(в)
предикатом `script:warn_density` — непрогон виден пре-пассу. Без
четвёртого детектор держится дисциплиной — это ход Lead.

**(г) На пути исполнения:** пре-пасс печатает чек 11(в) с предикатом;
канон ловит отказ формы. Суждение «какая доля — находка» остаётся за
Lead: порог запрещён нормой.

## §R. РЕШЕНИЯ Lead ПО РАЗВИЛКАМ

- **Р1 (знаменатель, главная):** принят **(а)** — свой знаменатель у
  каждого слоя, объявленный в реестре, с ОБЯЗАТЕЛЬНОЙ печатью абсолютных
  чисел рядом и словом `proxy` там, где база приблизительна. **Плюс (г)
  второй колонкой** — ставка на 100 вызовов: она сравнима между слоями,
  а доля — нет. Отклонён (б): доля слоя механически падает при росте
  чужого потока, это рецидив класса «элементы корректны, дефект в агрегате».
- **Р2 (единица счёта):** принят **(в)** — оба числа, доля от `calls`.
  Иначе слои с построчным потолком получат несопоставимо большие числа,
  и таблица снова соврёт ПОРЯДКОМ величины.
- **Р3 (носитель следа):** принят **(а)** — только `hook_success.stdout`,
  с печатью числа записей второго типа как контроля («вторых следов N —

- **Р4 (где живёт реестр):** принят **(а)** — `tools/warn_layers.json`.
  Отклонён (в) (реестром служит сам чек): чек прямо говорит, что литерал

- **Р5 (скоуп слоёв):** принят **(б)** — все живые слои, найденные

- **Р6 (корпус):** принят **(б)** — верхний уровень + `subagents/`.

- **Р7 (часы окна):** принят **(а)** — аргументы в локальном наивном
