## 3. Акцептанс-критерии

**AK1.** `_LAYER_A_FILES = ["README.md", "PROJECT_CHARTER.md",
"ANTI_GOALS.md", "PROJECT_PHILOSOPHY.md", "ARCHITECTURE_BOOT.md"]` —
константа кода, в порядке BOOT.md. Разбора markdown-заголовков на боевом
пути НЕТ (решение F-a, §9). Дрейф ловит пин AK10.

**AK2.** `layer_a_lines(root) -> list[str]` — ASCII-строки без переводов
строки внутри элементов. НИКОГДА не бросает: корпус обёрнут СВОИМ
try/except (образец `wiring_lines()`), непредусмотренный отказ вырождается
в одну строку
`AUTO-BOOT: Layer A inline unavailable (<деталь>) -- read the five files listed in BOOT.md yourself.`

**AK3. Обрамление, и закрывающая строка НЕСЁТ СЧЁТ** (это же — детектор
усечения, решение F6 §9):

```
--- BOOT LAYER A INJECTED (D-0103 hybrid) -- 5 files, 8279 bytes on disk ---
----- BEGIN README.md (2315 bytes) -----
<содержимое построчно, без префиксов и отступов>
----- END README.md -----
...
--- END BOOT LAYER A: 5 files, 209 lines, 8279 bytes emitted ---
```

Содержимое НЕ префиксуется и НЕ отступается (отступ ломал бы код-фенсы и
менял байты). Числа в обеих строках — ФАКТИЧЕСКИЕ, не константы.

**AK4. Лимит — ВАРН, НЕ БЛОК (решение оператора 2026-08-25).**
`LAYER_A_INLINE_WARN_BYTES = 16384`, объявлена как константа проекта, НЕ
выведена из 8279 (ось 14). Сумма `st_size` существующих файлов слоя A
считается ДО чтения.

- сумма ≤ порога → впрыск, обычное обрамление;
- сумма > порога → **впрыск ВСЁ РАВНО ПРОИСХОДИТ ПОЛНОСТЬЮ**, и ПЕРЕД
  блоком печатается строка
  `AUTO-BOOT: Layer A is <total> bytes, over the <cap> byte notice threshold -- injected in full; tell the operator the orientation layer has grown.`
- **Жёсткого потолка нет намеренно.** Второй сетью служат существующие
  строки BOOT BUDGET (WARN >90000, BREACH >100000 → boot-diet), они не
  трогаются. Обоснование записано, чтобы отсутствие потолка не читалось
  как недосмотр.
- Граничные тесты: ровно на пороге (варна нет), порог+1 (варн есть, впрыск
  полный).
- Замер по форме НА ДИСКЕ — тот же выбор, что у `boot_budget_lines`
  (известный класс, `docs/SIBLING_MAP.md`:686; новый экземпляр не
  заводится, факт назван в докстринге).

**AK5. ASCII-инвариант, и СМЫСЛ НЕ ТЕРЯЕТСЯ МОЛЧА** (условие оператора
2026-08-25: «главное чтобы смысл сохранился»). Каждая эмитируемая строка
обязана давать `.isascii() is True` — `→` не кодируется в cp1251, сырая
печать роняет write, а внешний `except` main() обнуляет ВЕСЬ контекст.
Реализация — НОВЫЙ `_ascii_content_line(s)`, НЕ `_ascii_sanitize` (тот
режет до 80 символов; отдельный тест: строка 500 символов проходит целиком):

- **таблица транслитерации** (смысл сохраняется): `—`→`--`, `–`→`-`,
  `→`→`->`, `←`→`<-`, `…`→`...`, `«»`→`"`, `“”`→`"`, `‘’`→`'`,
  неразрывный пробел→обычный;
- управляющие `[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]` вырезаются, `\t` живёт;
  `\r\n`/`\r` нормализуются при разбиении;
- **НЕОТОБРАЖЁННОЕ не заменяется молча.** Символ вне таблицы идёт в
  `encode("ascii","replace")`, НО каждый такой случай считается пофайлово,
  и перед закрывающей строкой печатается
  `[WARNING: N unmapped non-ASCII characters in <file> were replaced with '?' -- MEANING MAY BE LOST; tell the operator]`.
  Кириллица, попавшая в слой A будущей правкой, выдаст себя немедленно,
  а не сгниёт в вопросительных знаках.
- если сработала только таблица (потери смысла нет) — мягкая строка
  `[note: N non-ASCII characters transliterated for the console -- source files are unmodified]`.

**AK6. Чтение.** `read_text(encoding="utf-8", errors="replace")`.
Отсутствующий/нечитаемый (OSError, в т.ч. «путь оказался каталогом») →
вместо блока файла одна строка
`[missing: README.md -- not injected, read this one file yourself]`;
остальные впрыскиваются; счётчик в заголовке считает только фактически
впрыснутые. Пустой (0 Б) файл — НЕ missing: BEGIN/END без содержимого
(различение «пусто» и «нет» обязательно, отдельный тест). Все пять
отсутствуют → заголовок + пять `[missing: ...]` + закрытие.

**AK7. Гейтирование и позиция.** Содержимое печатается ТОЛЬКО когда
`autoboot_lines(source)` вернул непустой список:

### (ii) ПОЗИЦИОННЫЙ (R11(d)) — инварианты, ради которых выбрана точка

Ветка встаёт в `main()` между `autoboot = autoboot_lines(...)` (:2117) и
`output = "\n".join(all_lines)` (:2119).

- **B2 — ровно одна запись stdout.** Блок попадает в тот же `"\n".join`,
  не во второй write и не в `print()`. Пин `spy.write_calls == 1`
  (`test_f61_halfstate.py`:1088).
- **B1 — ack только после успешной выдачи.** Ветка ДО `sys.stdout.write`,
  ack остаётся ПОСЛЕ `flush()`. Пин расширяется маркером (B18).
- **Усечение не переезжает.** Блок ВНЕ `lines[:MAX_LINES]`, `context_lines`
  не удлиняются ни на строку: NOW/MODEL/BOOT BUDGET/OPEN DISPATCH/WIRING не
  вытесняются содержимым README. Пин B17.
- **Гейт по свежести неразрывен.** Содержимое привязано к тому же решению,
  что и директива (`if autoboot:`), а не к отдельной проверке `source`: две
  независимые проверки — пара требований, способная разойтись. Пин B13.
- **Fail-open строго сильнее.** Отказ сборки блока НЕ доходит до внешнего

## 11. Вердикт критика (t-587, БЛОКЕР) — что оказалось неверно в этой спеке

### БЛОКЕР 1 — недренирующий потребитель зависает на записи 10,7 КБ

После посадки хук пишет **10780 Б ОДНОЙ записью**. Замер критика:

```
ёмкость OS-пайпа (бинарный поиск):                          4096 Б
наименьшая единичная запись, вешающая недренирующего родителя: 4097 Б
LIVE   (1121 Б)  EXITED rc=0 in 0.60s
LANDED (10780 Б) *** BLOCKED, no exit after 8s ***
```

Хук, чей дедлайн на **чтение** stdin сделан отдельной машинерией именно
чтобы никогда не висеть, получает неограниченную блокирующую **запись**.
Первое жёсткое ограничение файла — «NEVER breaks session start»; зависший
старт хуже и обнуления контекста, и усечения.

**Почему спека упустила.** §8(в) рассматривала неизвестный потолок stdout
харнесса в ОДНОМ классе — усечении — и вопрос СНЯЛА, а не ответила.
**Блокировка есть ДРУГОЙ класс той же поверхности** («единственная запись
против неизвестного потребителя»), не назван ни в §5, ни в §6, ни в §8.
**И витнес к нему слеп ПО ФОРМЕ:** живой смоук с перенаправлением в файл
не блокируется — у файла нет ёмкости.

**Требуется до посадки:** ЗАМЕР — дренирует ли реальный харнесс stdout
своего SessionStart-хука параллельно. По п.6 гигиены «скорее всего
дренирует» основанием не служит.

### БЛОКЕР 2 — §7 неполон, канон краснеет при посадке

Симуляция посадки на КОПИИ дерева (боевой файл не тронут, п.7(г) гигиены):
базлайн `12 failed, 4046 passed`; посаженный мир `15 failed, 4009 passed`.
Те же 12 — шум копии без `.git`. **Три НОВЫХ падения, ни одного нет в §7:**
`test_session_context.py::test_main_b3_success_path_includes_model_and_boot_budget`
(`assert 37 <= 25` — существующий пин на потолок ВСЕГО stdout; инвариант
спеки «`context_lines` не удлиняются» соблюдён, а этот пин про другое) и два
`test_p4_stdin_deadline.py::test_k5_*[session_context]` (`TimeoutExpired`
после 9 с — проявление блокера 1).

### ФИКС 1 (корень) — подвал несёт байты С ДИСКА под этикеткой «emitted»

`emitted_bytes += size`, где `size` — `st_size` (`:1141`). Замер: заявлено
**8279**, эмитировано **8119**, дельта −160 (README −80, CHARTER −24,
ANTI_GOALS −9, PHILOSOPHY −22, ARCH_BOOT −25) = 126 CRLF + 34 транслита 3→2.

**Следствие отменяет замысел блока:** заголовок (`8279 bytes on disk`) и
подвал (`8279 bytes emitted`) равны **ПО ПОСТРОЕНИЮ** — оба есть сумма
`st_size`, взятая до чтения. Сессия, сверяющая «сходятся ли числа», получает
ОК на блоке, **усечённом по СЕРЕДИНЕ** — третий сценарий усечения, которого
спека не назвала (харнесс оставляет голову и хвост). Не перекрёстная
проверка, а тавтология, читающаяся как проверка. `files` и `lines` ЧЕСТНЫ —
считаются при эмиссии (`:1136-1137`). **Фикс:**
`emitted_bytes += len(ascii_line) + 1` рядом с `emitted_lines`.

### ФИКС 2 — сторож числа тоже тавтологичен

`test_b19_closing_line_counts_match_actual_emitted_content` (`:575`) сверяет
`bytes_n` с `sum(stat().st_size)` — с той же величиной, из которой число
получено. Фикстуры пишутся `write_text` → на Windows тоже CRLF, расхождение
живёт и в тестовом тракте, тест к нему слеп по построению.

### ФИКС 3 — дыра в самом обработчике fail-open (оба сайта)

Исключение, чей `__str__` бросает, проходит сквозь
`_layer_a_unavailable_line` (`:1041`): `layer_a_lines RAISED despite 'NEVER

### ФИКС 4 — у детектора усечения нет машинного слоя

§5(i)/§8(в)/F8 заводят расширение чека 13(ж) маркером `--- BOOT LAYER A`.
Это префикс **ОТКРЫВАЮЩЕЙ** строки, которую усечённый блок СОДЕРЖИТ. Чек
детектирует «директива есть, содержимого нет» и **усечение не детектирует
вовсе**; единственный детектор — внимание сессии к ОТСУТСТВИЮ строки, то
есть дисциплина, не названная среди трёх в §8(г). **Фикс: искать
ЗАКРЫВАЮЩИЙ литерал `--- END BOOT LAYER A:`.**

### ФИКС 5 — сторож, обученный молчать

В `test_main_startup_shows_boot_lite_and_autoboot` утверждение о наличии
блока стоит ВНУТРИ `if hasattr(sc, "_LAYER_A_FILES")`: при переименовании
константы ассерт молча пропустится и тест останется зелёным при
ОТСУТСТВУЮЩЕМ блоке. При посадке двухмирные гварды обязаны схлопнуться в
безусловные; спека этого не оговаривает.

### В2 — ослабления пина НЕТ, спека указывала не на тот тест

`test_f61_halfstate.py` не тронут; пин `spy.write_calls == 1` живёт в

Параметризованный маркерный тест использует `_MarkerRaisingStdout`, у

### Класс-полнота: настоящий промах ОДИН, и он мой

Класс **«байтовый бюджет меряется формой на диске»** (`SIBLING_MAP:686`)

## 12. РЕВИЗИЯ 2 — требования attempt 2 (R2(f): правка спеки Lead'ом, не новый драфт)

Решение оператора 2026-08-25: **релиз кита завтра.** Значит довод «замер не
портируется» перестал быть отложенным — хук уезжает на чужие машины через
сутки, и посылка «потребитель дренирует stdout» там не проверена никем.
**Машинерия дедлайна записи строится СЕЙЧАС.**

### R2-К1. ДЕДЛАЙН ЗАПИСИ — главный новый критерий

Форма ЗЕРКАЛИТ уже существующий в этом же файле stdin-хелпер
(`_read_stdin_bytes_deadline`, `session_context.py:659-713`) — та же
конструкция, не новая: **локальная копия, общий модуль запрещён**; демон-поток
делает работу, главный поток ждёт `join(deadline)`; значение берётся из env с
теми же правилами валидации (нечисловое, `<=0`, `> MAX` → дефолт).

- `_STDOUT_DEADLINE_DEFAULT = 5.0`, `_STDOUT_DEADLINE_MAX = 600.0`,
  env `OSLLM_STDOUT_TIMEOUT`.
- `_write_stdout_deadline(text) -> bool` — демон-поток выполняет
  `sys.stdout.write(text)` + `flush()`; главный поток `join(deadline)`.
  Возвращает `True`, если поток завершился в срок, `False` иначе.
- **На таймауте — `os._exit(0)` НЕМЕДЛЕННО, без всякого дальнейшего I/O.**
  Обоснование, которое обязано быть в докстринге: поток заблокирован в
  `write()` на полном пайпе; ЛЮБАЯ следующая запись (в stdout или stderr)
  блокируется по той же причине, поэтому попытка сообщить о таймауте сама
  становится вторым зависанием. Прецедент эскалации — батч П4 (`os._exit` по
  эмпирике K7). Код `0`, не `1`: хук не «упал», он выдал столько, сколько
  прошло, и старт сессии обязан продолжиться.
- **Инвариант B1 УЖЕСТОЧАЕТСЯ:** ack break-glass выполняется ТОЛЬКО когда
  `_write_stdout_deadline` вернул `True`. На `os._exit`-ветке ack не
  выполняется по построению — процесс умирает раньше.
- **Инвариант B2 СОХРАНЯЕТСЯ:** запись по-прежнему ОДНА
  (`sys.stdout.write(text)` целиком), просто исполняется на другом потоке.
  Дробить на чанки ЗАПРЕЩЕНО: при недренирующем потребителе дробление не
  помогает (блокирует суммарный объём, не размер вызова), а инвариант рушит.

**Что дедлайн покупает и чего НЕ покупает — назвать в докстринге явно.**
Покупает: старт сессии продолжается вместо зависания навсегда. НЕ покупает:
целостность выдачи — частично записанное остаётся в пайпе и извлечению не
подлежит. Композиция закрывает это место: **частичная запись → блок без
закрывающей строки → клауза директивы AK8 велит сессии прочесть пять файлов
самой.** Порядок сборки (`context_lines` → директива → блок) уже гарантирует,
что при обрыве выживает голова: NOW/MODEL/BOOT BUDGET и сама директива с
клаузой — то есть сессия узнаёт, что делать, ровно из того, что успело пройти.

### R2-К2. Байты в подвале — по ФАКТУ эмиссии (ФИКС 1 критика)

`emitted_bytes += len(ascii_line) + 1` рядом с `emitted_lines`, а НЕ
`st_size`. Заголовок сохраняет `N bytes on disk` (там `st_size` верен),
подвал несёт `N bytes emitted`. Числа обязаны РАСХОДИТЬСЯ на живых данных
(замер критика: 8279 on disk против 8119 emitted) — совпадение на файлах с
CRLF или транслитерацией есть признак того, что фикс не сделан.

### R2-К3. Тест подвала — не тавтология (ФИКС 2 критика)

`test_b19_...` обязан сверять объявленные числа с **фактически
эмитированным потоком**: распарсить собственный вывод по блокам BEGIN/END и
посчитать строки и байты. Сверка `st_size` с `st_size` запрещена явно.
Обязательный кейс: файл с CRLF и файл с транслитерируемым символом — на них
подвал ОБЯЗАН отличаться от суммы `st_size`.

### R2-К4. Дыра fail-open в самом обработчике (ФИКС 3 критика)

Тела ОБОИХ `except` (внутренний в `layer_a_lines`, внешний около
`_layer_a_unavailable_line`) оборачиваются в свой `try` с КОНСТАНТНЫМ
фолбэком без `str(exc)`. Тест: исключение, чей `__str__` бросает, — контекст
НЕ обнуляется, `NOW:` на месте, rc = 0.

### R2-К5. Двухмирные гварды не молчат (ФИКС 5 критика)

В тестах, где утверждение стоит внутри `if hasattr(sc, "_LAYER_A_FILES")`,
ветка СТАРОГО мира обязана нести собственное утверждение (симметрично
`test_autoboot_directive_block_is_ascii_and_exact`), чтобы переименование
константы давало ГРОМКОЕ падение, а не молчаливый пропуск. Плюс строка в
handoff: **при посадке гварды схлопываются в безусловные** — это обязанность
Lead, и она названа здесь, чтобы не обнаружиться красным каноном.

### R2-К6. Пин `MAX_LINES` на ВЕСЬ stdout (БЛОКЕР 2 критика)

`test_session_context.py::test_main_b3_success_path_includes_model_and_boot_budget`
несёт `assert len(out) <= sc.MAX_LINES` — про ВЕСЬ поток, тогда как
инвариант спеки про `context_lines`. **Решение Lead: пин правится по смыслу
— утверждать потолок на блоке boot-lite, а не на всей выдаче.** Файл входит
в owns ревизии 2. Форма правки обязана сохранить исходное намерение пина
(boot-lite не разрастается), а не просто поднять число.

### R2-К7. Детектор усечения ищет ЗАКРЫВАЮЩИЙ литерал (ФИКС 4 критика)

Блок для чека 13(ж), возвращаемый в отчёте, обязан искать
`--- END BOOT LAYER A:`, а не `--- BOOT LAYER A`: открывающую строку
усечённый блок СОДЕРЖИТ, и по ней усечение неотличимо. Посадка — Lead.

### R2-К8. Мелкие (ФИКС 6, 7 критика)

Готовый дифф `test_f61_halfstate.py` обязан быть В ОТЧЁТЕ (проверено: файл
не тронут, третьего маркера в параметризации нет) · мёртвое поле
