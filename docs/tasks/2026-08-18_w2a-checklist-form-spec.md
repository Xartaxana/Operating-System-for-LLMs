### A1. Форма машиночитаемой шапки чека

Носитель — однострочный HTML-комментарий ПЕРВОЙ строкой тела чека
(сразу под строкой жирного заголовка), с отступом тела:

```
<!--CHK 13(к)|src:журнал|pred:journal.parallel_groups|rules:RC§1/R4,RC§1/R11|status:живой|since:2026-08-09-->
```

Поля — фиксированный порядок, разделитель |, список значений через
запятую, пробелы внутри значений запрещены:

| поле | обяз. | значение |
|---|---|---|
| CHK <id> | да | <N> или <N>(<буква>); ОБЯЗАН совпадать с номером в тексте |
| src: | да | 1..4 значения из закрытого списка; ПЕРВОЕ — первичный источник, ключ группировки |
| pred: | да | ровно ОДИН предикат из закрытого списка (A3); дефолт при сомнении — always |
| rules: | да | 1..4 ссылки RC§<секция>/<токен> в docs/RULE_COVERAGE.md |
| status: | да | живой \| ретирован:<дата>;сторож:<id>;живость:<команда> \| деферред:<предикат-триггер> |
| since: | нет | дата посадки |
| note: | нет | короткая пометка без пробелов (напр. кандидат-ретирования(триггер:path.exists:tools/norm_retire.py)) |

Закрытый список src: журнал, журнал-AO3, git, git-AO3, cc_usage,
транскрипты, файлы, файлы-AO3, скрипт:<имя>, оператор.

Шапки подпунктов: подпункт получает СВОЮ шапку только когда его pred
или status отличаются от родительских (иначе наследует), и обязательно
если длиннее 10 строк. Преамбула чека принадлежит родителю: читается,
если жив хоть один подпункт; мёртв родитель и все подпункты — чек не
читается вовсе.

Лимиты формы (тест НА границе и ЗА ней): строка шапки ≤300 байт UTF-8;
значений src ≤4; шапок на id ≤1; длина id ≤12 символов.

Почему комментарий, а не видимая строка: рендер не засоряется,
человекочитаемую проекцию печатает пре-пасс. Альтернативы — Р1.

### A3. Пре-пасс — tools/calibration_prepass.py

Имя по сиблингу calibration_counts.py (семья calibration_*). Вход:
протокол (шапки + номера строк), журналы OS/AO3, git log обоих репо за
окно (git -C из кода), существование путей. Транскрипты и cc_usage
пре-пасс НЕ читает сознательно (цена/разрешения) — такие чеки
объявляют manual: и всегда живы.

CLI: --window-start <ISO> [--window-end] [--protocol] [--journal ...]
[--ao3-root] [--json] [--check-form] [--require-all]. Коды выхода:
0 — прогон состоялся; 1 — только у --check-form (дефекты формы);
2 — IO/аргументы.

Закрытый список предикатов v1 (без композиции — Р8): always ·
journal.any · journal.event:<E>[,agent=<A>][,deploy=…] ·
journal.field:<f>=<v> · journal.parallel_groups · git.any ·
git.paths:<glob>[,…][@OS|@AO3] · git.diff_lines:><N> ·
path.exists:<путь> · script:<имя> (всегда жив, печатает команду) ·
manual:<почему> (всегда жив).

ИНВАРИАНТ ПРЕДИКАТА (несущий): предикат обязан быть НЕОБХОДИМЫМ
условием непустоты чека — никогда не гасит окно с материалом. Не
выражается списком → manual:. Нарушение = spec-дефект автора шапки;
детектор — сам прогон: пропуски в notes calibrated, поздний материал в
«пустом» чеке → defect_found.

Выход: шапка окна; КОНТРОЛЬ ИСТОЧНИКОВ (с позитивным контролем пути);
секции §0–§5; на чек — вердикт ЖИВ/ПУСТ/РЕТИРОВАН/ДЕФЕРРЕД + диапазон
строк + причина; ИТОГ с процентом строк к чтению (он же измеритель
гейта (а) фазы, печатается каждым прогоном); список ПУСТЫХ ОКОН
(обязательны явной строкой в notes); строки ПЕРЕВЗВЕДЕНИЯ деферредов с
истинным триггером → находка.

Краевые поведения пре-пасса:
1. Пустое окно — exit 0, баннер, все не-always/manual ПУСТЫ, список
   целиком (пустота обязана попасть в notes, иначе неотличима от
   пропуска).
2. Чек без шапки — ЖИВ (fail-closed); при --require-all — ошибка
   формы; флаг включается коммитом M2 (темпоральный край A8.1).
3. Предикат на несуществующий источник — чек ЖИВ (fail-closed),
   причина дословно; для §5 — строка «внешний деплой недоступен» С
   позитивным контролем той же формы (isdir по корню нашего репо
   рядом, гигиена п.6).
4. Непарсящаяся строка журнала — предупреждение + журнальные чеки ЖИВЫ.
5. Сломанный пре-пасс (крэш/отсутствует/exit 2) — чек-лист читается
   ЦЕЛИКОМ + строка в notes; правило живёт в шапке чек-листа (A7).
6. Деферред × живой предикат — СТАТУС СИЛЬНЕЕ; но истинный
   предикат-ТРИГГЕР деферреда → строка ПЕРЕВЗВЕДЕНИЕ → находка.
7. status:ретирован — чек не читается; печатается строка со сторожем и
   командой живости, и эта команда входит в обязанности прогона.

### A4. Критерий ретирования и кандидаты ПОИМЁННО

Ретировать можно только при ВСЕХ трёх: (i) норма в RULE_COVERAGE с
режимом БЛОК-ХУК или ГЕЙТ КОММИТА (WARN/ВСПЛЫТИЕ/ДИСЦИПЛИНА — нет);
(ii) чек не приносит данных сверх видимых гейту (ни транскриптов, ни
cc_usage, ни смыслового вердикта); (iii) существует ИМЕНОВАННЫЙ
детектор живости гейта — вписывается в поле живость:. Нет детектора —
чек не ретируется, а ПРЕВРАЩАЕТСЯ в проверку живости сторожа.

Остаётся (ловит ОБХОД), если хоть одно: (а) сверяет декларацию с
внешним свидетельством (чеки 4, 5, 6; 13(л)); (б) у гейта есть
легальный обход (--no-verify, «оси: не-механизм», break-glass,
fail-open) — чек аудирует пользование (8, 26(в)); (в) скоуп гейта уже
нормы (25); (г) вердикт семантический (9/19/21/23); (д) чек И ЕСТЬ
детектор отказа гейта (26, 13(ж), 11(б)).

Различающая фраза: гейт отвечает «форма соблюдена?»; чек остаётся,
когда отвечает на вопрос, который гейт задать НЕ МОЖЕТ — «правда ли
пропущенное, и не обошли ли его».

Кандидаты: K1 чек 13(а) witness-присутствие — РЕТИРОВАТЬ (сторож
journal_validator + journal_echo; живость pytest
test_journal_validator; остаточный риск в стаб: строка, не дошедшая до
коммита, гейта не встречает — правда витнесса за 13(л)). K2 чек 12
фрагмент про оси/test_sibling_map_liveness — ОФОРМИТЬ ретированным
(де-факто уже). K3 чек 30(а) фрагмент «"judge" в whitelist» —
РЕТИРОВАТЬ ФРАГМЕНТ (JUDGE_BASIS_VALUE + энум лист-классов в
валидаторе; остальное 30(а) остаётся — класс (а)). K4 чек 12 паритет
DECISIONS — НЕ СЕЙЧАС: сторож norm_retire.py на диске ОТСУТСТВУЕТ
(t-485 в полёте; позитивный контроль глобом 9/10) — статус живой +
note:кандидат-ретирования(триггер:path.exists); пре-пасс напечатает
ПЕРЕВЗВЕДЕНИЕ. K5 чек 13(в) — НЕ целиком: первая фраза ретируема
(FAILURE_CLASSES в валидаторе), остаток — детектор отказа
calibration_counts (класс (д)); расщепление — смысловая правка, вне
W2a. Остальные (2,3,6,8,9,19,21,22,23,25,26,29,31,13(л)) — ОСТАЮТСЯ по
классам (а)–(д).

Итог по объёму: чистых кандидатов три фрагмента (K1,K2,K3) ≈ 1 КБ.
Ретирование в W2a — не байтовый рычаг (см. A6).
