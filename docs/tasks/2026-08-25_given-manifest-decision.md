## 1. Механика, как она есть (сверено дословно)

У `tools/dispatch_gate.py` ДВА независимых слоя про манифест.

**Слой 1, БЛОКИРУЮЩИЙ** (`:674`, `:1074-1078`):

```python
MANIFEST_GIVEN_RE = re.compile(r"\bдано\b|\bgiven\b", re.IGNORECASE)
OWNS_WORD_RE = re.compile(r"\bowns\b", re.IGNORECASE)
has_manifest = bool(MANIFEST_GIVEN_RE.search(prompt)) and bool(OWNS_WORD_RE.search(prompt))
if not has_manifest:
    return 2, BLOCK_MESSAGE_NO_MANIFEST
```

Булев поиск ДВУХ СЛОВ где угодно в тексте. Не путей, не перечисления, не
содержимого. Только на пишущих диспатчах builder'у. Процитированная
декларация тоже снимает блок (комментарий в коде; под это есть отдельный
слой `manifest_quoted_warn`).

**Слой 2, WARN-ONLY** — `given_path_warn()`: берёт названные в тексте
путь-токены, проверяет существование на диске; в exit code НЕ участвует,
на заблокированной ветке не печатается. Понятия «указатель на спеку»
отдельно от «перечисленного файла» нет НИ НА ОДНОМ слое.

**Инцидент.** Диспатч узла A был заблокирован. Первичный диагноз
координатора — «не разобрался заголовок owns» — ОПРОВЕРГНУТ измерением:
owns распознался штатно, а слова «given»/«дано» в промпте не было ни разу
(корзина делегирована указателем «прочти целиком»). Следствие: сегодня
достаточно написать слово рядом с указателем, и гейт пропустит.

**Норма молчит.** R11 запрещает указатель для DoD БУКВОЙ («a bare pointer
to a spec file or an earlier event is NOT a DoD»), для given говорит лишь
«enumeration of injected files/data». Явного запрета указателя для given
нет ни в `CLAUDE.md`, ни в `docs/POLICY_FULL.md`, ни в `PROCESS/**` —
проверено с позитивным контролем в каждом из трёх мест (t-583).

## 2. Вердикт резервного яруса, раунд 1 (t-584)

Ярус сверен замером, не заявлением: транскрипт воркера, 24 записи модели,
все `claude-fable-5`.

**(А) Указатель засчитывается — как НОСИТЕЛЬ перечисления, не как его
замена.** Манифест исполнен, когда стоит ПОМЕЧЕННАЯ МАРКЕРОМ декларация
корзины («Дано: …»), содержимым которой может быть либо инлайн-перечень,
либо указатель на персистированную спеку, которая сама несёт перечень.
**Один переход** — цепочки нелегальны буквой правила, гейту их резолвить
не надо. Голое «прочти целиком X» без маркера манифестом НЕ является.

**Owns остаётся строго инлайн** — у него, в отличие от given, есть
МАШИННЫЙ ПОТРЕБИТЕЛЬ: `owns_gate` пишет `logs/owns_registry.jsonl` из
текста промпта, указатель убил бы сверку пересечений R4 молча. Асимметрия
не эклектика, а факт архитектуры; инцидент это подтверждает буквально —
owns был инлайн и распознался, отсутствовал только given.

**(Б) Пятый вариант: 3 + два довеска.** (i) переименовать сообщение и
строку реестра в то, что реально меряется; (ii) ТЕМ ЖЕ ХОДОМ закрыть
асимметрию нормы строкой про (А); (iii) детерминированный остаток «маркер
есть, декларации за ним нет» получает WARN-слой (не блок) на существующей
машинерии, промоция в блок — по эмпирике ликов.

**Чем резерв опроверг наклон Lead (rename-only):** переименование лечит
ловушку диагноста и не лечит ловушку диспетчера — рациональный ход
координатора после rename — дописать слово рядом с указателем, и
переименованное сообщение сделает ритуал ОФИЦИАЛЬНО ЧЕСТНЫМ. Дословно:
«честность о том, что ты декорация, декорацией быть не перестаёт». Слово
гейта становится прокси чего-то реального только если тем же ходом закрыта
норма (А). Плюс: наклон отвечал на (Б), оставляя (А) висеть, а вопрос
очереди был нормативным; и читал D-0063 половинно — вторая половина
обязывает детерминированный остаток посадить в код.

**Попутная поправка Lead:** принцип «один носитель на факт» ошибочно
приписан оси 2 карты (она — контуры измерения); принцип живёт в D-0038.

## 4. Пересмотр резерва, раунд 2 (t-589)

**(А) НЕ ИЗМЕНИЛОСЬ.** Резерв признал критерий отката сработавшим и провёл
пересмотр, а не отмахнулся. Итог: **аргумент свежести СНЯТ как разбитый**
(17/2 против инлайна, плюс подозрение общего знаменателя Z1, из-за
которого сами 22.9% под вопросом). Но (А) на нём не стояло — оно стоит на
трёх ногах, замерами не задетых, и получило четвёртую:

1. один носитель на факт (D-0038) + живая практика персистированных спек (R4.f);
2. асимметрия owns/given по машинному потребителю — свойство архитектуры;
3. достаточность судит ярус выше (D-0063, чек 23) независимо от формы корзины;
4. **НОВАЯ — З3**: прямое измерение ЦЕЛИ нормы. Манифест существует не
   затем, чтобы токены резолвились, а затем, чтобы исполнитель получил
   достаточную корзину.

Плюс довод асимметрии отказа: **мёртвый указатель отказывает ГРОМКО и
ДЁШЕВО** (ловится `given_path_warn` в момент диспатча; не пойман —
исполнитель упирается первым же чтением), протухшая инлайн-копия
отказывает ТИХО и ДОРОГО — работой по несвежим фактам до возврата. Норма
должна легализовать форму с громким отказом.

**Разрешение противоречия З2/З3 — не усреднение.** Они меряют РАЗНЫЕ
звенья: З2 — синтаксический прокси («существует ли токен сейчас»), З3 —
ИСХОД («получил ли исполнитель корзину»). Когда прокси и исход расходятся,
исход старше по иерархии доказательств — прокси существовал только как его
заместитель. Механическое объяснение расхождения: если гниение указателей
ГРОМКОЕ, оно не конвертируется в reject'ы — сигнатура «токены гниют,
диспатчи проходят» ровно та, что дали З2+З3 вместе. Вдобавок числитель З2
правдоподобно загрязнён тем самым классом, что велено чинить: GIVEN_PATH
стрелял по own-owns путям (артефактам, несуществующим ПО ЗАМЫСЛУ), а
эвристики классификатора («вне секции → POINTER», «единственный токен →
POINTER», секция given без верхней границы) сгребают такие токены в
POINTER. **То есть З2 бьёт не по (А), а по чистоте популяции warn-слоя.**

**Оговорка резерва в обратную сторону, приведена честно:** 20
pointer-диспатчей с нулём reject'ов против базовой ставки ~10% — это
ожидаемые ~2, и ноль при таком n СКЛОНЯЕТ, но не доказывает (вероятность
нуля при равных ставках ~0.12). Три согласных окна — довод, статистической
силы одного окна нет.

**(Б): ядро стоит, довесок (iii) ИЗМЕНЁН.**

- **(i) rename** — стоит, от чисел не зависел.
- **(ii) строка нормы (А) в реестр R11/D-0073** — стоит, усилен З3, садится
  сейчас: ни один недомер его не касается.
- **(iii) MANIFEST-RITUAL warn — НЕ СТРОИТЬ СЕЙЧАС.** Три причины:
  (1) его измерительная база `warn_density` под подозрением общего
  знаменателя — строить сторожа, чей детектор отказа стоит на возможно
  битом счётчике, есть ровно то «вслепую», против чего написан узел I;
  (2) он РИСКУЕТ стать ЧЕТВЁРТЫМ экземпляром нового класса «warn-слой с
  популяцией, неудовлетворимой по построению»: легальная data-only корзина
  (R11(j), «дано: вывод ниже») не несёт путь-токена, а «инлайн-содержимое
  присутствует» детерминированно дёшево не решается — слой срабатывал бы
  на легальной форме ПО ПОСТРОЕНИЮ; (3) З1 дал базу 4/28 БЕЗ корреляции с
  вредом — половина собственного критерия промоции не отвечена.
  **Замена, держащая D-0049:** остаток переводится в режим
  ДИСЦИПЛИНА+НАЗВАННЫЙ ДЕТЕКТОР — З1-классификатор уже существует как
  воспроизводимый инструмент с фикстурой и негативным контролем;
  регистрируется как калибровочный прогон (сосед чека 11(в)) + атрибуция
  чеком 23. Промоция в живой warn-слой — по ТРОЙНОМУ триггеру: знаменатель
  починен, популяционная дисциплина нового класса определена,
  З1-корреляция со spec-reject'ами измерена и ненулевая.

**Достаточность чисел — раздельно.** Для (А), rename и строки нормы —
ДОСТАТОЧНЫ (стоят на конструкции и норме, З3 добавляет исходную эмпирику,
недомеры бьют по замерным инструментам, не по норме). Для (iii) и любых
будущих ставок на доли warn-слоёв — НЕДОСТАТОЧНЫ.

## 4а. Вердикт критика по замерам (t-585, БЛОКЕР) — почему числа не годятся

Критик воспроизвёл замер собственным кодом и получил **побайтово те же
числа** — инструмент честен в том, что делает. Дефект не в исполнении, а в
том, что именно эти числа измеряют.

**З2 — пропорция есть артефакт версии гейта.** Фильтр
`_filter_given_candidates` (сужения Р1/Р2) появился коммитом **786cf81 от
2026-08-20 22:43** — через ДЕВЯТЬ ЧАСОВ после закрытия окна №8 (окно
кончается 13:51). Замер реплеит исторические промпты СЕГОДНЯШНИМ гейтом.
Разложение критика прогоном:

| условия реплея | диспатчей / токенов | классы |
|---|---|---|
| текущий гейт + существование сейчас (как в замере) | 12 / 19 | INLINE 2, POINTER 17 |
| гейт окна №8 + существование сейчас | 19 / 40 | **INLINE 20, POINTER 20** |
| дельта, снятая Р1/Р2 | — | INLINE 18, POINTER 3 |

Историческая правда (27 сайдкара) лежит внутри вилки 19…45 гейта окна.
**«POINTER 89.5%» превращается в 50/50, как только гейт возвращён к версии
окна.** Гипотеза исполнителя про региональный путь ОПРОВЕРГНУТА прогоном:
живой `given_path_warn()` на тех же 118 промптах даёт ровно 12, как и bare;
region-aware — строгое подмножество bare и дефицит объяснить не может.

**З2 — классификатор не имеет класса, которому принадлежит большинство
данных.** Критик распечатал контекст всех 19 токенов: это в массе
`Форма сдачи: сиблинги tools/negative_lint_md.py и ...`,
`Copy the ENTIRE current tools/session_context.py verbatim into a new
sibling file ...`, `предложи схему: PROCESS/checks/CHK-NN.md` (ШАБЛОН
имени, не путь), путь в списке НЕ-ЦЕЛЕЙ. Это TEMPORAL-артефакты (R11c),
которые диспатч СОЗДАЁТ — сиблинги D-0069, сдаваемые под сиблинг-именем и
потому объявленные ВНЕ owns-секции, отчего Р2 их не ловит. Числитель З2
меряет **чистоту популяции warn-слоя**, а не роль токена. Подозрение
резерва подтверждено поимённо: 13–17 из 19.

**З3 — «три окна» это одно окно, посчитанное дважды.** Пересечение по
`tool_use_id`: prev-A есть строгое подмножество #8, а по ПИШУЩИМ диспатчам
множества ТОЖДЕСТВЕННЫ (31 = 31, пересечение 31). prev-B по пишущим не
пересекается с #8 вовсе и в pointer-плечо не вносит НИЧЕГО. Сводные
«pointer 20/20, 0 rejected» — те же 10 диспатчей дважды.

**З3 — половина pointer-плеча есть артефакт инструмента.**
`classify_z3_form` определяет секцию токена по `prompt.find()`, то есть по
ПЕРВОМУ вхождению; путь, названный сперва в прозе и затем перечисленный в
`given`, засчитывается прозе. При учёте ЛЮБОГО вхождения в секции:
pointer 10 → **5**, inline 18 → **23** (перевернулись t-504, t-447, t-513,
t-525, t-526 — у каждого 3–5 перечисленных путей в given).

**З3 — 26% связанных исходов структурно не могут дать reject.** Линкер
берёт ПЕРВОЕ событие с тем же task_id и отдаёт `other:<event>`, а штатная
форма репо — critic entry `delegated` на открытый task_id. Таких 7 из 27, и
они сидят в ЗНАМЕНАТЕЛЕ. Все семь (t-509, t-511, t-516, t-525, t-526,
t-529, t-532) закончились `accepted`. **Это подкласс II того самого класса,
воспроизведённый ВНУТРИ измерителя.** Честные знаменатели: pointer 0/7,
inline 2/13.

**З3 — ноль не сигнал.** Точный двусторонний тест Фишера для 0/10 против
2/17: **p = 0.5157**; вероятность нуля из 10 при базовой ставке 11.8% —
**0.286**. Резерв оперировал числом 0.12, посчитанным для n = 20 — то есть
для УДВОЕННОЙ дубль-счётом популяции.

**Что из этого следует для решения.** Падает ЧЕТВЁРТАЯ нога (А) и снятие
«аргумента свежести» — снятие надо считать необоснованным (что не делает
аргумент верным: он просто не измерен). **Ноги 1–3 нормативно-архитектурные,
замерами не задеты и находками критика тоже.** Критик прямо оговорил, что
не принимает и не отменяет (А) — это уровень оператора (R11a).

Ирония, зафиксированная критиком: требование спеки «регулярки ИМПОРТИРОВАТЬ,
а не копировать» — верное для живого инструмента — **на историческом корпусе
гарантирует ровно тот дрейф версии, от которого защищает.** Для реплея
правильная форма — пин гейта на коммит, живший в окне, либо явная этикетка
«контрфакт: что сказал бы СЕГОДНЯШНИЙ гейт о старых промптах».
