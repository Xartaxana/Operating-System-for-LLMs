## Что делает механизм

После установки/апгрейда кита у хоста МАШИНА сверяет, что каждое
правило И КЛАУЗА поставленной политики физически присутствует в
дереве хоста (после host-restoration), и предъявляет список
недовезённого; апгрейд получает письменный протокол слияния
CLAUDE.md, при котором restoration не может стереть новый политблок.
Класс: недовоз ec4e6f0 у Dog (файлы доехали, ~14 блоков политики —
нет; чеки-сторожа доехали и смотрели в пустоту).

## §M1. Протокол слияния CLAUDE.md при апгрейде (нормативно; из t-464 §1.3)

1. Карвинг-аут: правило апгрейда «host branch is RESTORED on top of
   the new kit base» остаётся для КОДА; для CLAUDE.md и прочих
   носителей политики (роль-файлы, PROCESS/*.md) — запрещено
   поимённо: восстановление хост-ветки поверх новой базы возвращает
   старый политблок целиком (класс ec4e6f0).
2. Адаптации хоста внутри политблока выписываются СПИСКОМ (что/где/
   зачем) — из строк леджера и сравнения с предыдущей поставленной
   ревизией; список именуется в коммите апгрейда.
3. Содержимое между маркерами BEGIN/END supervised-delegation policy
   заменяется содержимым CLAUDE.md новой ревизии кита ЦЕЛИКОМ.
4. Каждая адаптация из шага 2 накладывается на новый блок отдельным
   пунктом и ПРОВЕРЯЕТСЯ на присутствие; непроверенный пункт =
   невыполненный шаг.
5. Вне маркеров — не трогать (хост-локальные секции).
6. Маркеров нет (Path A/доконвенционная установка): ставятся этим же
   ходом (BEGIN перед первым заголовком политики, END в конце), факт
   — строкой леджера; до постановки якоря ищутся по всему файлу,
   после — внутри блока.
7. Закрытие — parity-прогон по ФИНАЛЬНОМУ дереву; любая правка между
   прогоном и коммитом обнуляет прогон.
   Парная инструкция рядом: манифест якорей заменяется ЦЕЛИКОМ,
   CLAUDE.md целиком НЕ заменяется никогда.

## §M3. Края поведения (нормативно; из t-464 §1.5, с правками v2)

Лимиты (тест на границе и за ней): якорь ≤200 символов, одна
строка (200 ок / 201 exit 2); якорей 0 → exit 2 (страховка от
вечнозелёного), 1 → норма, 500 MISSING → печатаются ВСЕ (усечение
воспроизвело бы недовоз-невидимку); файл хоста 5 МБ / 20k строк —
проходит, потолок сознательно не вводится (фраза в докстринге).
Пустое/отсутствующее: манифест отсутствует/битый/[] → exit 2, одна
строка; файл хоста отсутствует → по леджеру (K6); пуст → все якоря
MISSING, exit 1; не-UTF8 → errors=replace + WARN-строка, сравнение
продолжается; леджера нет → bootstrap (MISSING-FILE → UNKNOWN,
шапка «no ledger found; checked: ...», exit 1); леджер найден, 0
распознанных строк → отдельный статус в шапке (F2); --root не
каталог → exit 2; нераспознанный статус строки → UNKNOWN.
Форма: CRLF→LF и BOM-снятие с ОБЕИХ сторон в одной функции;
сравнение буквальное подстрокой, не regex (тест с .* и [);
не-ASCII якоря/пути — UTF-8 stdout (errors=replace); model: во
фронтматтере роль-файлов исключён из парити по конструкции (хост
привязывает свою модель). Темпоральный: манифест и запись «Install
parity:» рождаются этим механизмом — мир-до (апгрейды до ревизии
механизма: отсутствие записи НЕ находка; условие в тексте чека),
мир-после (отсутствие = находка), создатели названы (запись — шаг
Upgrade mode вместе с Kit snapshot revision; манифест — шаг
kit-release). Позиционный: прогон ПОСЛЕ копирования и restoration/
слияния, ПЕРЕД коммитом; инвариант 1 — проверка видит коммитуемое
дерево; инвариант 2 — parity НЕ звено pre-commit (цепочка первого
коммита свежей установки и так fail-closed; см. также B2: notices
невидимы для enforcement_probe, пин-тест). Конфликтные пары: парность
против законной адаптации → приоритет леджера/waiver'ов (waiver без
host_equivalent file:line и reason — не waiver); немедленный ремонт
хоста против моратория → мораторий связывает КИТ, ремонт хоста =
поставка по D-0082 при безопасном касании (прецедент 37100b3);
«обязана уметь падать» против «хук не валит сессию» → CLI громкий
(exit 1/2), канал notices неблокирующий — два носителя, два
контракта; путь-как-ключ против косметики путей → host_path в
waiver переопределяет, без него переименованный файл → UNKNOWN
(громко), не MISSING (обвинение); restoration против парности →
карвинг-аут §M1 п.1.
