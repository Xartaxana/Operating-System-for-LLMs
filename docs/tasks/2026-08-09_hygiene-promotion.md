# 2026-08-09 — Промоция гигиены: warn → блок

Триггер: слово оператора «делай батч промоции гигиены» (после прямого
вопроса «почему его оставляем на калибровку? почему нельзя закончить
сейчас?», снявшего отсрочку). Носитель по D-0080. Журнал: t-370, t-372…
Класс: последний живой пункт находки (7) калибровки №6.

## Почему отсрочка была снята

Записанное основание отсрочки — «нужен замер окна при неизменном
скоупе, иначе нечего сравнивать». Инструмента замера не существовало;
батч раздела 1 его построил (разбивка `permission_audit` по классам
гигиены). Основание растворилось, а ссылка на отсрочку продолжала
повторяться по инерции — вопрос оператора это вскрыл.

Дожидаться объёма бессмысленно: решение упирается не в объём, а в
законность использования по каждому классу. За всю историю 3275 команд
с классом на 9799 вызовов; за окно неизменного скоупа — 9 на 84.
Обе цифры говорят одно: паттерн жив, warn его не останавливает.

## Что вскрылось перед решением — и изменило его

**Классификатор путает код с данными.** Проба Lead: оба попадания
блокирующего класса «журнал мимо Edit/Write» за сутки оказались
командами, которыми воркеры ТЕСТИРОВАЛИ классификатор — паттерны лежали
данными внутри тела `python -c` и heredoc. При живом блоке была бы
заблокирована проверочная работа критика и билдера.

Следствия: (1) маскировка вложенного — предусловие блока, не улучшение;
(2) исторические числа замера загрязнены на неизвестную долю.

**Два края, найденные драфтом:**
- п.2 гигиены ПРЕДПИСЫВАЕТ поднимать прокси из `gateway`, п.3 запрещает
  `cd`-префикс — блок запретил бы документированную форму. Решение:
  узкое исключение для `gateway`; отдельным вопросом в очередь — можно
  ли поднимать прокси без `cd` вообще.
- маскировка ОТКРЫВАЕТ дыру в живом блоке журнала (реальная запись
  внутри heredoc перестанет ловиться). Блок при write-намерении есть её
  КОМПЕНСАТОР, а не дополнение — оба обязаны встать одним ходом.
