## 3. Форма правила (акцептанс-ключ 1)

### 3.1 Точный синтаксис

```
RN. **<Императив-заголовок>**: <ЯДРО: 3–8 строк, настоящее время,
без дат/номеров задач/прецедентов/обоснований; если ядро даёт
концессию, оно НАЗЫВАЕТ её словом «except as listed below»>

| RN | when | duty | src |
|---|---|---|---|
| a | <триггер: когда именно> | <обязанность: что делать/что запрещено> | D-NNNN |
| b | ... | ... | F-NN |
```

Правила синтаксиса (нормативные для будущих правок — см. §5, п.
«мета-строка»):

1. Заголовочная ячейка первой колонки — номер правила (`| R8 |`), строки
   помечены буквами; внешняя цитируемая форма ID — **R8.b** (стабильный
   якорь вместо сегодняшнего «второй абзац R8»).
2. Ядро — 3–8 строк. Перечисления, уже имеющие список-форму (5-пунктный
   чеклист R11, 7 пунктов гигиены), в счёт строк ядра НЕ идут (развилка Р1).
3. Одна строка реестра = ОДИН триггер → ОДНА обязанность. Потолок строки
   400 символов (выведен из самого длинного УЦЕЛЕВШЕГО нормативного
   амендмента — клауза D-0102 в R1, ≈340 символов, + запас в одну клаузу);
   выше потолка — признак, что в строку заползло обоснование: обоснование
   уезжает в POLICY_FULL, в строке остаётся указатель.
4. src несёт ТОЛЬКО идентификатор носителя (D-NNNN / F-NN), без дат и
   номеров задач (совместимость с диетой 08-16); амендмент без решения —
   развилка Р2.
5. Символ | внутри ячейки экранируется \|.
6. Дословный carrier_anchor никогда не пересекает границу ячейки
   (схлопывание пробелов в escape_check не убирает |).
7. Правило без исключений таблицы НЕ несёт (пустой шапки-таблицы быть не
   должно).

## 5. Бюджетная строка (акцептанс-ключ 3)

**Норма** — одна строка в шапке CLAUDE.md:

```
Size budget: this file is capped at <WARN> bytes (breach <BREACH>);
an amendment to a rule is a ROW in that rule's registry, never a
paragraph in its core, and its rationale goes to docs/POLICY_FULL.md
(axis-4 pair, same commit). Breach → boot-diet, CLAUDE.md layer.
```

Строка делает коммит механизменным по D-0065 → строка RULE_COVERAGE тем
же коммитом.

**Машинный слой** (рекомендация): СУФФИКС существующей строки
boot_budget_lines() в session_context.py: под порогом вывод не меняется,
при пробое — `... | CLAUDE.md: 34210 / 33800 OVER -> boot-diet (CLAUDE
layer)`. Цена: одна константа + ~10 строк кода + 4 теста.

**Число**: не круглое; после последнего коммита миграции:
CLAUDE_WARN = ceil(размер × 1.03 / 100)×100 (3% ≈ 4–5 строк реестра —
запас на амендменты одного окна); CLAUDE_BREACH = ceil(WARN × 1.05 /

УРОВНЯ — уровень выносится развилкой Р3.

**Процедура при пробое**: нового скилла/чека НЕ заводить — абзац в слой

### 7.2 Временной край (R11(i))
До последнего коммита миграции персонального порога НЕТ (временный не
заводится); создаёт его последний коммит после финального замера.
Миграция прервана на середине → порог НЕ вводится.

### 7.3 Пустой/отсутствующий вход
Правило без исключений → блока реестра нет; пустая шапка таблицы —
дефект (скрипт ловит). CLAUDE.md отсутствует → boot_budget_lines уже
печатает [missing] и 0 Б; персональный порог печатает missing, НЕ «под
бюджетом». Правило из одних исключений — ядро не может быть пустым.

### 7.4 Конфликтующие пары
- P1 «ядро 3–8» × «норма не теряется»: излишек → строка реестра →
  указатель; удаление запрещено; не вмещается → ядро + реестр + свой
  уже-список (развилка Р1).
- P2 src без дат × прослеживаемость — развилка Р2.
- P3 дословные якоря × сжатие: якорь выигрывает всегда; перепин — только
  решением Lead тем же коммитом.
- P4 персональный порог × суммарный boot-порог: независимы; пробой
  одного при здоровом втором → только соответствующий слой, пропуск
  слоя — явной строкой отчёта, не молча.
- P5 CRLF × LF: хук меряет st_size рабочего дерева (+≈590 Б при CRLF);
  порог — по числу С ДИСКА; witness несёт ОБА числа + core.autocrlf.

### 7.5 Позиционный край (R11(ii))
Реестр стоит сразу после ядра. Инвариант позиции: читатель ТОЛЬКО ядра
не может прийти к более РАЗРЕШИТЕЛЬНОМУ выводу, чем ядро+реестр. Строка,
дающая концессию, анонсируется в ядре («except as listed below»);
сужающая — анонса не требует.
