Владелец: docs/tasks/2026-08-25_kit-v0.9.0-release.md. Вход: вердикты

Драфт Lead с dispatch_skipped (R2c): спеки собираются механически из

## Общие правила порта (все узлы)

1. Словарь кита — АНГЛИЙСКИЙ. Штабные якоря (t-NNN, номера штабных
   чеков, D-NNNN) НЕ переносятся буквально: переименовывать
   дескриптивно (прецедент t-295). Ссылка на решение → короткая
   смысловая фраза в комменте/докстринге.
2. Синк ПО ФУНКЦИИ, не по структуре (прецедент wiring_check t-409):
   сознательные отличия кита сохраняются (standalone wiring_check,
   sqlite raw-text off, CASES 12-command, EN-маркеры, свои пути).
   Проверка «не сломал ли отличие by design» — явный вопрос в отчёте.
3. Референс-реализация — штабной файл-близнец в корне репо; порт —
   правка toolkit-твина Edit/Write (никаких байт-копий целиком:
   у твинов есть сознательные расхождения).
4. Тесты: где портируется функция — портируется её тест-покрытие
   (адаптированное под кит: пути, EN-маркеры, без штабных пинов).
   Штабные тесты, пиняющие ЧИСТО штабные артефакты, не переносятся —
   перечислить такие в отчёте с причиной.
5. Прогон-witness узла: `python -m pytest <owned test files> -q` из
   корня репо (перечислить файлы явно). Полный toolkit-прогон и канон
   штаба — обязанность координатора при слиянии (R4.a), не узла.
6. Хуки кита должны остаться самодостаточными (без импортов из
   штабного tools/ — только внутри toolkit/tools/).
7. Правки только в своих owns. Замеченные аналоги вне owns — строкой
   в отчёте, без расширения скоупа.
