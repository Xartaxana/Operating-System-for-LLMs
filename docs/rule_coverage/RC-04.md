## rc4-hygiene-v5

Норма ядра: канонические формы команд (без cd-префикса, без `2>&1`) —
`tools/hygiene_gate.py` (PreToolUse Bash\|PowerShell), константа
`V5_ENABLED`.

История включения V5: V5 включён ходом Lead 2026-08-09 после трёх
критик-входов и семишаговой пробы живости (два живых DENY в треке
включения). Принцип: DENY требует определённости, неоднозначное
деградирует в warn.

Полная классификация классов вывода:
БЛОКИРУЕТСЯ (DENY) — cd/Set-Location первым statement'ом (разделители
`;`/`&&`/перевод строки) с целью-корнем ЭТОГО репо; ` 2>&1` вне
кавычек при отсутствии heredoc-маркера `<<` на маскированном тексте;
журнал мимо Edit/Write (с 07-23) + PowerShell-формы
Add-Content/Set-Content/Out-File (08-09).
WARN — цель-не-корень (замена названа в тексте), неоднозначные формы,
python -c/heredoc без изменений.

Известные ограничения ЯВНОЙ очередью: позиционный обход cd не первым
statement'ом (24 живых на замер посадки, триггер «рецидив после
включения»); путаница код/данные журнального класса сохранена
сознательно (деградация открыла бы реальный обход).

Откат: Edit константы `V5_ENABLED` (путь сверен: claim_control_gate
без deny-ветки), два subprocess-пина упадут при откате — тихого
отката нет.

Сужение узла F.3 (2026-08-20) — «журнал мимо Edit/Write» по живому
ложному блоку на ЧИТАЮЩЕМ вызове: у statement'а с read-only головой
(grep/rg/cat/head/tail/wc/sed, `_READ_ONLY_HEAD_RE`) редирект `>`
больше не считается журнальной записью сам по себе, поэтому
`grep -c "x" logs/routing-log.jsonl 2>/dev/null` ДО денялась, теперь
проходит МОЛЧА; форма с ` 2>&1` денается уже по классу редиректа.
Правка БЕЗУСЛОВНА — НЕ стоит за `PYC_DENY_ENABLED` (замер: 10
расхождений на 252 командах при выключенном переключателе).

Состояние переключателя `PYC_DENY_ENABLED`: ветка «python -c/heredoc →
БЛОК» в дереве ЕСТЬ, но НА 2026-08-20 ПЕРЕКЛЮЧАТЕЛЬ ВЫКЛЮЧЕН —
`PYC_DENY_ENABLED = False`, класс остаётся WARN; переключение — акт
Lead, тем же ходом правятся строка карты и чек 25.
