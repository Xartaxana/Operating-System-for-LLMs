## rc7-chk26

Норма ядра: чек 26 — policy-as-code гейты штаба; постановка ПО ФАКТУ
ФАЙЛА `.claude/settings.json`, три группы покрытия детектором
молчания, проба живости кода отдельной осью.

Критерий засчитывания рода греп-попадания (2026-08-09, N5; ред.
2026-08-19: после диеты W2c-2 сводки-дубликата в файле больше нет —
нулевой результат грепа достижим и валиден при положительном контроле
формы) — полная таксономия трёх родов попадания живёт в
PROCESS/checks/CHK-26.md (раздел «Таксономия трёх родов
греп-попадания»), здесь не повторяется.

История переформулировки постановки (а): состав command-хуков
`.claude/settings.json` сверяется ПО ФАКТУ ФАЙЛА, не по жёсткому числу
— переформулировано 2026-08-09 (F-56, прежний жёсткий список «шесть
хуков» разошёлся с фактом двенадцати command-хуков).

История критерия покрытия (в): способна ли проверка обнаружить
МОЛЧАНИЕ гейта, не только его ошибочное срабатывание (2026-08-09,
тихая смерть — режим отказа, ради которого существует правило 10(в));
по этому критерию состав групп (4/3/5) уточнён 2026-08-09 — параллельная
ветвь применила критерий строже и нашла третьего частично покрытого
(`journal_echo`, добавлен в «ПОКРЫТЫ ЧАСТИЧНО»).

Разбор ПОЧЕМУ каждый частично покрытый — частично: `dod_gate`/
`main_gate` — подпункт (в) ловит ТОЛЬКО ложный блок по существующим
событиям `gate_log`, у него нет ОЖИДАНИЯ ПРИСУТСТВИЯ — нет утверждения
вида «в окне с такими-то фактами записи gate_log обязаны быть», поэтому
тихая смерть неотличима от «блоков не было». `journal_echo` — СВОЙ
пробел, другой формы: подпункт (г) сверяет ПРИСУТСТВИЕ маркера
вырожденного режима «echo base: HEAD-diff fallback», здоровым
состоянием считается его ОТСУТСТВИЕ — утверждения «на N журнальных
аппендов обязано быть N срабатываний эха» нет, поэтому полностью
мёртвый хук даёт ноль маркеров, картина неотличима от исправной
работы.

СВЕЖЕЕ СНИМКА (2026-08-10, t-387): проба живости КОДА
`hook_liveness_probe` (чек 26(д)) закрывает дыру «детектора живости
нет нигде» для всех хуков разом — снимок трёх групп ЯДРА остаётся
классификацией по НАЗВАННОСТИ предметом проверки отказа, а не по
живости кода; при чтении сверяться с 26(д) и датами.
