## rc1-r13-judge

Норма ядра: R13/D-0094, судья принимает только лист-класс; отклонение
от D-пути — с записанной причиной.

Провенанс: абзац «ОТКЛОНЕНИЯ ОТ ЛИСТ-МАРШРУТА» подпункта (д) чека 30
заведён 2026-08-20 узлом B по находке F5. ДО этого узла R13(a) ядра
CLAUDE.md называл чек 30 своим оконным детектором отклонений, но шага
машинной сверки в самом чеке не было вовсе — экземпляр находки F-41
(протухшая ссылка «сторож есть по названию, а не по факту»).

Полная формула критерия (сокращена в ядре карты до «без `basis
"judge"` — обязана быть причина»): каждый ЛИСТ-КЛАССОВЫЙ диспатч окна,
чей `accepted` не несёт `basis "judge"`, обязан иметь ЗАПИСАННУЮ
ПРИЧИНУ в notes события той же задачи; голое `basis
"critic"/"queued-to-lead"` причиной НЕ считается (оно не объясняет,
почему диспатч не прошёл через судью, а лишь называет, кто принял);
пустое окно (листовых диспатчей не было) отмечается ЯВНО с позитивным
контролем (число проверенных диспатчей). Дословность самого судейского
промпта — отдельный подпункт 30(а), сторож `judge_prompt_pin`.

## rc1-r7-role

Норма ядра: R7/D-0083 расширение — заявленный АГЕНТ (роль) диспатча
обязан сходиться с фактическим `subagent_type` транскрипта воркера, не
только модель (2026-08-09, разрыв калибровки №6, t-348).

Механика резолюции роли: `tools/dispatch_gate.py` ЧАСТЬ B (PreToolUse
Task\|Agent, вызывается ПОСЛЕ `decide()`, не блокирует, только
предупреждает) — `role_type_warn` резолвит роль перебором
`.claude/agents/*.md` (`_find_agent_role_model`): совпадение по имени
файла (stem) ИЛИ по полю `name:` фронтматтера, регистронезависимо (не
прямой путь по `subagent_type` — тот не называет файл роли напрямую).
У найденной роли берётся `model:` фронтматтера и сверяется семейство с
заявленным ярусом лейбла диспатча; расхождение или неизвестная роль →
WARN «ROLE-TYPE WARN» в контекст. Ручная сверка ОСТАЁТСЯ основой чека 4
(D-0042) в обоих мирах — машинный слой ДОПОЛНИТЕЛЬНЫЙ, не замена.

Полная классификация принятой дыры (флаг ядра — «группа НЕ ПОКРЫТЫ
чека 26»): живости/отказа самого хука зарегистрированного детектора
НЕТ (2026-08-09, F-56 досылка B11 t-367). По трёхгрупповому критерию
чека 26 (способна ли проверка обнаружить МОЛЧАНИЕ гейта, не только его
ошибочное срабатывание) `dispatch_gate` — в группе «НЕ ПОКРЫТЫ»
(нулевое покрытие, вместе с `owns_gate`/`claim_control_gate`/
`search_control_gate`/`negative_lint`), а НЕ в группе «ПОКРЫТЫ
ЧАСТИЧНО» (`dod_gate`/`main_gate` — у тех подпункт (в) хотя бы ловит
ложный блок по существующим событиям `gate_log`; у `dispatch_gate` нет
и этого). Чек 26 держит только ПОСТАНОВКУ (сверку состава
`.claude/settings.json` по факту файла, чек 26(а)), не отказ.
Ремедиация детектора — в очереди вместе с остальными четырьмя нулевого
покрытия.

## rc1-w2b8-form

Норма ядра: Phase 5 W2b-8 (2026-08-19) — форма правил R1/R2/R4/R8/
R11/R13 (ядро 3-8 строк + реестр «triggers→duty→src») + персональный
порог размера CLAUDE.md.

Форма правил: ядро 3-8 строк + реестр «triggers→duty→src», строка
реестра ≤523 Б, `src` двухносительно резолвится POLICY_FULL/
DECISIONS_FULL, escape_allowlist-якоря не разорваны ячейкой.

История порога CLAUDE.md (два перевывода): персональный порог
CLAUDE_WARN/CLAUDE_BREACH поверх общего boot-бюджета; исходный
храповик BREACH=36115 — размер на старте фазы. ПЕРВЫЙ ПЕРЕВЫВОД
(W2c-4, слово Архитектора, 2026-08-20): файл вырос легитимными нормами
узла C до 36102, старые пороги давали вечный OVER — WARN=36700/
BREACH=37000 по той же формуле W2b от нового замера; рост порога —
только словом оператора, не молча. ВТОРОЙ ПЕРЕВЫВОД ТОГО ЖЕ ДНЯ —
решение Р-О4, слово оператора (узел G ремедиации): две кодификации,
которых потребовал чек 23 калибровки №7, подняли файл до замера
36900 Б при WARN=36700; четыре диеты ядра подряд исчерпали кандидатов
на срез, порог перевыведен ПО ФАКТУ формулой `WARN =
ceil(36900*1.015/100)*100 = 37500`, `BREACH = WARN + 300 = 37800`
(носитель — `tools/session_context.py`, провенанс — комментарий там
же); машинного сторожа у этой ДИСЦИПЛИНЫ перевывода нет — ось 14
SIBLING_MAP. Доп.: `CLAUDE_BREACH` — число БЕЗ кодового пути, ни одна
ветка не читает его; порог OVER считается только по `CLAUDE_WARN`
(грепом с позитивным контролем: живые чтения `CLAUDE_WARN` найдены).

Полнота исключений (Р12(B)): ассерт полноты `converted∪exempted` =
R1..R13+R11a — R3/R5/R6/R7/R9/R10/R12/R11a остаются без реестра
(«банк карт» в transfer-maps до первого амендмента), не забытые, а
СОЗНАТЕЛЬНО исключённые формой Р12(B).

Границы синтетики: 8/9 (границы ядра-строки) и 523/524 (граница
строки реестра) доказаны отдельными граничными тестами `tools/
test_norm_form.py`, негативный контроль (снятый ключ) обязателен на
каждом.
